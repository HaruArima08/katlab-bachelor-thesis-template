\subsection{要求仕様情報リスト生成処理}\label{subsec:req_extraction}
要求仕様情報リスト生成処理は、CSVファイルで記述した要求仕様書と初期設定(\ref{sec:config}節参照)で記述した設定ファイルvitt.yamlの2つを入力とし、
対応関係分析部(\ref{sec:correspondence-analysis}節で後述)およびTCVダイアグラム生成部(\ref{sec:diagram-generation}節で後述)で用いる、
要求仕様情報リストを生成する処理である。
図\ref{fig:req_extraction_composition}に、本処理の流れを示す。

\begin{figure}[tp]
    \begin{center}
        \includegraphics[width=13cm]{images/04/req_extraction_composition.png}
        \caption{要求仕様情報リスト生成処理の流れ}
        \label{fig:req_extraction_composition}
    \end{center}
\end{figure}

本処理は、以下の4つの処理を順に実行し、要求仕様情報リストを生成する。
\begin{enumerate}
    \item 要求仕様記述項目抽出処理
    \item 要求仕様文生成処理
    \item 対応付け可否判定処理
    \item 階層関係抽出処理
\end{enumerate}

以降、それぞれの処理について説明する。

\subsubsection{要求仕様記述項目抽出処理}\label{subsubsec:req_item_extraction}
要求仕様記述項目抽出処理は、要求仕様書の各要求仕様から、要求仕様記述項目 (\cref{tb:reqspec_item}参照)の情報を抽出する処理である。
具体的には、CSVファイルで記述した要求仕様書を入力とし、要求仕様記述項目と対応する要求仕様情報オブジェクトの一部のプロパティに値を代入した要求仕様情報オブジェクトのリストを出力する。

本処理の流れを、以下に示す。
\begin{enumerate}
    \item 空のリストを用意する。
    \item CSVファイルの要求仕様書を、DictReader関数(\ref{sec:Python}節を参照)を用いて1行ずつ読み込み、
    CSVの1行目のヘッダー行 (要求仕様ID,要求仕様名,前提条件,トリガー,システム応答) をカラムとして取得し、2行目以降の各データ行を、ヘッダー行のカラムをキーとした辞書形式で取得する。
    \item 取得した各辞書データについて、以下の処理を順に行う。
    \begin{enumerate}
        \item 空の要求仕様情報オブジェクトを生成する。
        \item 辞書のキーに対応する値を、要求仕様情報オブジェクトの各プロパティに代入する。
        \begin{enumerate}
            \item idプロパティに``要求仕様ID''をキーとした値を代入する。
            \item nameプロパティに``要求仕様名''をキーとした値を代入する。
            \item preconditionプロパティに``前提条件''をキーとした値を代入する。
            \item triggerプロパティに``トリガー''をキーとした値を代入する。
            \item responseプロパティに``システム応答''をキーとした値を代入する。
        \end{enumerate}
        \item 生成した要求仕様情報オブジェクトを、$1$. で用意したリストの末尾に追加する。
    \end{enumerate}
    \item 要求仕様情報オブジェクトのリストを出力する。
\end{enumerate}

\subsubsection{要求仕様文生成処理}\label{subsubsec:req_text_gen}
要求仕様文生成処理は、要求仕様記述項目抽出処理で生成した、
要求仕様情報オブジェクトのprecondition、trigger、responseの各プロパティの文字列と、
初期設定(\ref{sec:config}節参照)で記述した設定ファイルvitt.yamlのsystem\_nameの値を組み合わせ、
要求仕様文(\ref{sec:EARS}節参照)を生成する処理である。
具体的には、要求仕様記述項目抽出処理で生成した要求仕様情報オブジェクトのリスト、および、設定ファイルvitt.yamlの2つを入力とし、
要求仕様文を表すdescriptionプロパティに値を代入した状態の要求仕様情報オブジェクトのリストを出力する。

本処理の流れを、以下に示す。
\begin{enumerate}
    \item 設定ファイルvitt.yamlからsystem\_nameの値を取得する。
    \item 入力として受け取った要求仕様情報オブジェクトのリストの要素数、すなわち、要求仕様情報オブジェクトの数だけ、以下の処理を繰り返す。
    \begin{enumerate}
        \item 要求仕様情報オブジェクトのリストの先頭から、未処理の要求仕様情報オブジェクトを1つ取り出す。
        \item 要求仕様文の部分文字列を格納する空のリストを用意する。
        \item $2$.(a)で取り出した要求仕様情報オブジェクトからprecondition、trigger、responseの各プロパティの値を取得する。
        \item 取得した各プロパティの値に応じて、以下の処理を行う。
        \begin{enumerate}
            \item preconditionプロパティの値が空文字列でない場合\\
            ``\{precondition\}場合''という形式の部分文字列を$2$.(b)で用意したリストの末尾に追加する。
            \item triggerプロパティの値が空文字列でない場合\\
            ``\{trigger\}時''という形式の部分文字列を$2$.(b)で用意したリストの末尾に追加する。
            \item responseプロパティの値が空文字列でない場合\\
            $1$.で取得したsystem\_nameの値とresponseプロパティの値を用いて、
            ``\{system\_name\}は\{response\}べきである''という形式の部分文字列を$2$.(b)で用意したリストの末尾に追加する。
        \end{enumerate}
        \item リスト内の部分文字列を先頭から順に読点(、)で結合し、要求仕様文を生成する。
        \item 生成した要求仕様文を、$2$.(a)で取得した要求仕様情報オブジェクトのdescriptionプロパティに代入する。
    \end{enumerate}   
    \item 要求仕様情報オブジェクトのリストを出力する。
\end{enumerate}

\subsubsection{対応付け可否判定処理}\label{subsubsec:req_traceability}
対応付け可否判定処理は、各要求仕様がテストケースと対応付け可能かどうかを判定する処理である。
具体的には、要求仕様文生成処理が出力した要求仕様情報オブジェクトのリストを入力とし、テストケースと対応付け可能かどうかを示すis\_traceableプロパティに値を代入した状態の要求仕様情報オブジェクトのリストを出力する。
本研究では、類似度算出処理(\ref{subsec:similarity_calculation}節で後述)において、\cref{tb:traceability}に示した、
要求仕様の対応付け要素 (「前提条件」、「トリガー」、「システム応答」)とテストケースの対応付け要素 (「事前条件」、「操作」、「期待出力」)のそれぞれのテキスト間の類似度を算出し、
その結果に基づいて対応関係抽出処理(\ref{sec:traceability_extraction_processing}節で後述)において、要求仕様とテストケースの対応関係を抽出する。
そのため、\ref{sec:words}節で述べた、対応付け不可能な要求仕様は、テストケースとの対応付けの対象外と判定する。
例えば、図\ref{fig:reqspec_example_input_analysis_section}に示す要求仕様ID「REQ-1」は、要求仕様の対応付け要素のうち、「前提条件」、「トリガー」の値が空文字列となっているため、対応付け不可能な要求仕様であり、対応付けの対象外と判定する。

本処理の流れを、以下に示す。
\begin{enumerate}
    \item 入力として受け取った要求仕様情報オブジェクトのリストの要素数、すなわち、要求仕様情報オブジェクトの数だけ、以下の処理を繰り返す。
    \begin{enumerate}
        \item 要求仕様情報オブジェクトのリストの先頭から、未処理の要求仕様情報オブジェクトを1つ取り出す。
        \item 取り出した要求仕様情報オブジェクトからprecondition、trigger、responseの3つのプロパティの値を取得する。
        \item 取得した3つのプロパティの値によって、以下の処理を行う。
        \begin{itemize}
            \item 3つのプロパティの値が全て空文字列でない場合\\
            テストケースとの対応付け可能な要求仕様と判定し、is\_traceableプロパティにtrueを代入する。
        \end{itemize}
        \begin{itemize}
            \item 3つのプロパティのうち、いずれか1つのプロパティの値が空文字列であった場合\\
            テストケースとの対応付け不可能な要求仕様と判定し、is\_traceableプロパティにfalseを代入する。
        \end{itemize}
    \end{enumerate}
    \item 要求仕様情報オブジェクトのリストを出力する。
\end{enumerate}

\subsubsection{階層関係抽出処理}\label{subsubsec:req_hierarchy}
階層関係抽出処理は、要求仕様IDの命名規則 (\ref{subsec:reqspec}節参照) に基づき、要求仕様間の親子関係の情報を抽出する処理である。
具体的には、対応付け可否判定処理が出力した要求仕様情報オブジェクトのリストを入力とし、要求仕様間の親子関係を示すparent\_idおよびchildren\_idsプロパティに値を代入した状態の要求仕様情報オブジェクトのリストを、要求仕様情報リストとして出力する。
出力は、対応関係分析部(\ref{sec:correspondence-analysis}節で後述)およびTCVダイアグラム生成部(\ref{sec:diagram-generation}節で後述)に渡す。
階層関係抽出の例を、表\ref{tb:hierarchy_example}に示す。

本処理の流れを、以下に示す。
\begin{enumerate}
    \item 入力として受け取った要求仕様情報オブジェクトのリストから、idプロパティの値をキー、リスト内の要求仕様情報オブジェクトへの参照を値とする辞書を生成する。
    \item 要求仕様情報オブジェクトのリストの要素数、すなわち、要求仕様情報オブジェクトの数だけ、以下の処理を繰り返す。
    \begin{enumerate}
        \item 要求仕様情報オブジェクトのリストの先頭から、未処理の要求仕様情報オブジェクトを1つ取り出す。
        \item 取り出した要求仕様情報オブジェクトのidプロパティの値をハイフン(\texttt{-})で分割し、分割結果の要素数を確認する。
        例えば、``REQ-1-2''の場合、分割結果は[``REQ'' , ``1'', ``2'']であり、要素数は3個である。
        \item 分割結果の要素数に応じて、以下の処理を行う。
        \begin{itemize}
            \item 要素数が2個の場合\\
            親要求仕様を持たない要求仕様情報オブジェクトのため、以降の処理は行わず、
            リスト中の次の要求仕様情報オブジェクトに対して$2$.(a)からの処理を行う。
            表\ref{tb:hierarchy_example}の例では、``REQ-1''および``REQ-2''がこの場合に該当する。
            例えば、``REQ-1''の分割結果は[``REQ'' , ``1'']であり、parent\_idの値はNoneとなる。
            \item 要素数が3個以上の場合\\
            親要求仕様を持つ子要求仕様情報オブジェクトのため、以下の処理を行う。
            \begin{enumerate}
                \item 分割結果の末尾要素を除いた部分をハイフン(\texttt{-})で結合し、親要求仕様のidプロパティの値を生成する。
                例えば、表\ref{tb:hierarchy_example}の``REQ-1-1-1''の場合、分割結果[``REQ'' , ``1'' , ``1'', ``1'']のうち、末尾の``1''を除いた[``REQ'' , ``1'', ``1'']をハイフン(\texttt{-})で結合し、親要求仕様のidプロパティの値``REQ-1-1''を生成する。
                \item 生成した親要求仕様のidプロパティの値をキーとして、$1$.で生成した辞書から親要求仕様情報オブジェクトへの参照を取得する。
                \item 取得した参照を用いて、親要求仕様情報オブジェクトと$2$.(a)で取得した子要求仕様情報オブジェクトの間に、親子関係を双方向に記録する。
                具体的には、子要求仕様情報オブジェクトのparent\_idプロパティに親要求仕様情報オブジェクトのidプロパティの値を代入し、親要求仕様情報オブジェクトのchildren\_idsプロパティのリストに子要求仕様情報オブジェクトのidプロパティの値を追加する。
                表\ref{tb:hierarchy_example}の例では、``REQ-1-1-1''のparent\_idは``REQ-1-1''であり、``REQ-1-1''のchildren\_idsは``REQ-1-1-1''を含む。
            \end{enumerate}
        \end{itemize}
    \end{enumerate}
    \item 要求仕様情報オブジェクトのリストを、要求仕様情報リストとして出力する。
\end{enumerate}

\subsection{テストケース情報リスト生成処理}\label{sec:testcase-data-extraction}
テストケース情報リスト生成処理は、CSVファイルで記述したテストスイートを読み込み、
対応関係分析部(\ref{sec:correspondence-analysis}節で後述)およびTCVダイアグラム生成部(\ref{sec:diagram-generation}節で後述)で用いる、
テストケース情報リストを生成する処理である。

本処理の流れを、以下に示す。
\begin{enumerate}
    \item 空のリストを用意する。
    \item テストスイートのCSVファイルの数だけ、以下の処理を繰り返す。
    \begin{enumerate}
        \item 未処理のテストスイートのCSVファイルを1つ取得する。
        \item 取得したCSVファイル名から拡張子(.csv)を除去し、テストスイート名として保持する。
        例えば、ファイル名が「ログインテスト.csv」の場合、「ログインテスト」をテストスイート名として保持する。
        \item CSVファイルのテストスイートを、DictReader関数(\ref{sec:Python}節を参照)を用いて1行ずつ読み込み、
        CSVの1行目のヘッダー行 (テストケースID, テストケース名, 事前条件, 操作, 期待出力)をカラムとして取得し、2行目以降の各データ行を、ヘッダー行のカラムをキーとした辞書形式で取得する。
        \item 取得した各辞書データについて、以下の処理を行う。
        \begin{enumerate}
            \item 空のテストケース情報オブジェクトを生成する。
            \item 辞書のキーに対応する値を、テストケース情報オブジェクトの各プロパティに代入する。
            \begin{enumerate}
                \item idプロパティに``テストケースID''をキーとした値を代入する。
                \item nameプロパティに``テストケース名''をキーとした値を代入する。
                \item preconditionプロパティに``事前条件''をキーとした値を代入する。
                \item operationプロパティに``操作''をキーとした値を代入する。
                \item expected\_outputプロパティに``期待出力''をキーとした値を代入する。
                \item test\_suiteプロパティに$2$.(b)で保持したテストスイート名を代入する。
            \end{enumerate}
            \item 生成したテストケース情報オブジェクトを、$1$.で用意したリストの末尾に追加する。
        \end{enumerate}
    \end{enumerate}
    \item テストケース情報オブジェクトのリストを、テストケース情報リストとして出力する。
\end{enumerate}

\subsection{形態素解析処理}\label{sec:morphological_analysis}
形態素解析処理は、要求仕様情報リストとテストケース情報リストがそれぞれ含む対応付け要素の文字列を、MeCab (\cref{sec:Mecab}参照)を用いて形態素に分割し、各形態素の基本形と品詞を取得する処理である。
具体的には、入力解析部から受け取った、要求仕様情報リストとテストケース情報リストの2つを入力とし、要求仕様形態素データリストおよびテストケース形態素データリストを、それぞれ出力する。
出力は、重要単語抽出処理(\ref{sec:imp_word}節で後述)に渡す。

要求仕様形態素データリストは、各要求仕様の対応付け要素のテキストを形態素に分割し、各形態素の基本形と品詞を格納したリストである。

要求仕様形態素データは、以下に示す$4$つの情報を持つ。
本研究では、形態素情報とは、各形態素の基本形と品詞からなる情報のことを表す。
\begin{itemize}
    \item 要求仕様ID: 要求仕様を一意に識別するID
    \item 前提条件の形態素情報リスト: 前提条件のテキストを形態素に分割し、各形態素の基本形と品詞の対を保持したリスト
    \item トリガーの形態素情報リスト: トリガーのテキストを形態素に分割し、各形態素の基本形と品詞の対を保持したリスト
    \item システム応答の形態素情報リスト: システム応答のテキストを形態素に分割し、各形態素の基本形と品詞の対を保持したリスト
\end{itemize}

テストケース形態素データリストは、各テストケースの対応付け要素のテキストを形態素に分割し、各形態素の基本形と品詞を格納したリストである。

テストケース形態素データは、以下に示す$4$つの情報を持つ。
\begin{itemize}
    \item テストケースID: テストケースを一意に識別するID
    \item 事前条件の形態素情報リスト: 事前条件のテキストを形態素に分割し、各形態素の基本形と品詞の対を保持したリスト
    \item 操作の形態素情報リスト: 操作のテキストを形態素に分割し、各形態素の基本形と品詞の対を保持したリスト
    \item 期待出力の形態素情報リスト: 期待出力のテキストを形態素に分割し、各形態素の基本形と品詞の対を保持したリスト
\end{itemize}

本処理の流れを、以下に示す。
\begin{enumerate}
    \item 入力解析部 (\cref{sec:input-data-analysis}参照) の出力である、要求仕様情報リストとテストケース情報リストを入力として読み込む。
    \item 要求仕様情報リストが持つ要求仕様情報オブジェクトの数だけ、以下の処理を繰り返し、要求仕様形態素データを生成する。
    \begin{enumerate}
        \item 要求仕様情報リストの先頭から、未処理の要求仕様情報オブジェクトを$1$つ取り出す。
        \item 取り出した要求仕様情報オブジェクトが対応付け不可能な要求仕様の場合(is\_traceableプロパティの値がfalseの場合)\\
            以降の処理は行わず、$2$.(a)の処理に戻る。
        \item 取り出した要求仕様情報オブジェクトから、要求仕様IDおよび$3$つの対応付け要素(「前提条件」、「トリガー」、「システム応答」)の文字列を抽出する。
        図\ref{fig:str_mapping_element}に、図\ref{fig:reqspec_example_input_analysis_section}で示した要求仕様ID「REQ-1-3」の要求仕様情報オブジェクトから抽出する対応付け要素の文字列の例を示す。

        \begin{figure}[tp]
            \begin{center}
                \includegraphics[width=17cm]{images/04/str_mapping_element.png}
                \caption{対応付け要素の文字列の例}
                \label{fig:str_mapping_element}
            \end{center}
        \end{figure}

        \item 抽出した$3$つの対応付け要素のそれぞれの文字列について、以下の処理を実行する。
        \begin{enumerate}
            \item 空の形態素情報リストを用意する。
            \item 全角英数字を半角英数字に変換する前処理を行う。
            これは、「３」と「3」、「Ａ」と「A」のような表記揺れを統一し、類似度算出処理(\cref{subsec:similarity_calculation}節で後述) での精度を向上させる目的がある。
            \item MeCabを用いて、$2$.(d)ii. の前処理後の文字列を形態素に分割し、基本形と品詞を抽出する。
            \item 抽出した基本形と品詞の対を形態素情報として、$2$.(d)i.で用意した形態素情報リストに追加する。
            図\ref{fig:morpheme_info_list}に、図\ref{fig:str_mapping_element}で示した対応付け要素の文字列から生成した形態素情報リストの例を示す。

            \begin{figure}[tp]

    \begin{enumerate}
        \item テストケース情報リストの先頭から、未処理のテストケース情報オブジェクトを$1$つ取り出す。
        \item 取り出したテストケース情報オブジェクトから、テストケースIDおよび$3$つの対応付け要素(「事前条件」、「操作」、「期待出力」)の文字列を抽出する。
        \item 抽出した$3$つの対応付け要素のそれぞれの文字列について、$2$.(d)と同様の処理を実行する。
        \item テストケースIDと$3$つの対応付け要素の形態素情報リストから成る、テストケース形態素データを生成する。

\end{enumerate}

\subsection{重要単語抽出処理}\label{sec:imp_word}
重要単語抽出処理は、形態素解析処理(\cref{sec:morphological_analysis}節参照)で生成した要求仕様形態素データリストおよびテストケース形態素データリストから、重要単語をそれぞれ抽出する処理である。
具体的には、形態素解析処理から受け取った、要求仕様形態素データリストとテストケース形態素データリストの2つを入力とし、要求仕様重要単語データリストおよびテストケース重要単語データリストを、それぞれ出力する。
出力は、類似度算出処理(\ref{subsec:similarity_calculation}節で後述)に渡す。

本研究では、重要単語として名詞、動詞、複合名詞を抽出する。
名詞は要求仕様やテストケースにおいて、対象物や概念を表し、動詞はシステムの動作や振る舞いを表すため、要求仕様とテストケースの内容を特徴付ける単語として、重要な意味を持つ。
また、複合名詞は、2個以上の名詞が連続した単語と定義し、先頭に接頭辞を伴う場合も含める。
本研究では、複合名詞は単独の名詞よりも要求仕様やテストケースの内容を具体的に表すことができるため、抽出対象とする。

要求仕様重要単語データリストは、各要求仕様の対応付け要素から抽出した重要単語を格納するリストである。

要求仕様重要単語データは、以下に示す$4$つの情報を持つ。
\begin{itemize}
    \item 要求仕様ID: 要求仕様を一意に識別するID
    \item 前提条件の重要単語リスト: 前提条件の形態素情報リストから抽出した名詞、動詞、複合名詞からなるリスト
    \item トリガーの重要単語リスト: トリガーの形態素情報リストから抽出した名詞、動詞、複合名詞からなるリスト
    \item システム応答の重要単語リスト: システム応答の形態素情報リストから抽出した名詞、動詞、複合名詞からなるリスト
\end{itemize}

テストケース重要単語データリストは、各テストケースの対応付け要素から抽出した重要単語を格納するリストである。

テストケース重要単語データは、以下に示す$4$つの情報を持つ。
\begin{itemize}
    \item テストケースID: テストケースを一意に識別するID
    \item 事前条件の重要単語リスト: 事前条件の形態素情報リストから抽出した名詞、動詞、複合名詞からなるリスト
    \item 操作の重要単語リスト: 操作の形態素情報リストから抽出した名詞、動詞、複合名詞からなるリスト
    \item 期待出力の重要単語リスト: 期待出力の形態素情報リストから抽出した名詞、動詞、複合名詞からなるリスト
\end{itemize}

本処理の流れを、以下に示す。
\begin{enumerate}
    \item 形態素解析処理の出力である、要求仕様形態素データリストとテストケース形態素データリストを入力として読み込む。
    \item 要求仕様形態素データリストが持つ要求仕様形態素データの数だけ、以下の処理を繰り返し、要求仕様重要単語データを生成する。
    \begin{enumerate}
        \item 要求仕様形態素データリストの先頭から、未処理の要求仕様形態素データを1つ取り出す。
        \item 取り出した要求仕様形態素データから、要求仕様IDおよび3つの対応付け要素の形態素情報リストを抽出する。
        図\ref{fig:important_words}の①に、図\ref{fig:morpheme_info_list}におけるトリガーの形態素情報リストを抽出した例を示す。

        \begin{figure}[tp]
            \begin{center}
                \includegraphics[width=17cm]{images/04/important_words.png}
                \caption{図\ref{fig:morpheme_info_list}におけるトリガーの形態素情報リストから生成した重要単語リストの例}
                \label{fig:important_words}
            \end{center}
        \end{figure}

        \item 抽出した$3$つの対応付け要素の形態素情報リストそれぞれについて、以下の処理を実行する。
        \begin{enumerate}
            \item 名詞リスト、動詞リスト、複合名詞候補リスト、複合名詞リストの4つの空のリストを用意する。
            \item 形態素情報リストを先頭から順に走査し、各形態素の品詞に応じて、以下の処理を行う。
            \begin{itemize}
                \item 形態素の品詞が名詞の場合
                    \begin{itemize}
                        \item 形態素情報リスト内の次の形態素が名詞以外の場合\\
                        対象の名詞を$2$.(c)i.で用意した名詞リストに追加する。
                        図\ref{fig:important_words}の②に示す例では、「辺」、「さ」、「入力」を名詞リストに追加する。
                        \item 形態素情報リスト内の次の形態素が名詞の場合\\
                        名詞以外の形態素が現れるまで形態素情報リストを走査し、連続する名詞を結合して$2$.(c)i.で用意した複合名詞候補リストに追加する。
                        図\ref{fig:important_words}の②に示す例では、「文字」と「列」が連続する名詞であるため、結合して「文字列」を複合名詞候補リストに追加する。
                    \end{itemize}
                \item 形態素の品詞が接頭辞の場合
                    \begin{itemize}
                        \item 形態素情報リスト内の次の形態素が名詞以外の場合\\
                        形態素情報リスト内の次の形態素を走査する。
                        \item 形態素情報リスト内の次の形態素が名詞の場合\\
                        名詞以外の形態素が現れるまで形態素情報リストを走査し、接頭辞と連続する名詞を結合して$2$.(c)i.で用意した複合名詞候補リストに追加する。
                    \end{itemize}
                \item 形態素の品詞が動詞の場合\\
                $2$.(c)i.で用意した動詞リストに追加する。
                図\ref{fig:important_words}の②に示す例では、「する」を動詞リストに追加する。
            \end{itemize} 
            \item 複合名詞の妥当性判定\label{enum:妥当性判定}\\
            複合名詞候補リスト内の各単語に対して、以下の2つの条件を全て満たす場合、複合名詞と判定し、$2$.(c)i.で用意した複合名詞リストに追加する。
            図\ref{fig:important_words}の②に示す例では、「文字列」を複合名詞リストに追加する。
            \begin{itemize}
                \item 文字数が$20$文字以下である\\
                $20$文字を超える複合名詞は、異常に長い文字列として除外する。
                \item 同一文字のみから成る3文字以上の単語ではない\\
                例えば、「年年年」のように、同一文字のみから成る3文字以上の単語は、意味のある複合名詞ではないと判定し、除外する。
            \end{itemize}

            \item 重要単語リストの結合\\
            名詞リスト、動詞リスト、複合名詞リストを結合し、対応付け要素の重要単語リストとして保持する。
            図\ref{fig:important_words}の③に、生成した重要単語リストの例を示す。
        \end{enumerate}
        \item 要求仕様IDと$3$つの対応付け要素の重要単語リストから成る、要求仕様重要単語データを生成する。
    \end{enumerate}

    \item テストケース形態素データリストが持つテストケース形態素データの数だけ、以下の処理を繰り返し、テストケース重要単語データを生成する。
    \begin{enumerate}
        \item テストケース形態素データリストの先頭から、未処理のテストケース形態素データを$1$つ取り出す。
        \item 取り出したテストケース形態素データから、テストケースIDおよび$3$つの対応付け要素の形態素情報リストを抽出する。
        \item $2$.(c)と同様の処理を実行する。
        \item テストケースIDと$3$つの対応付け要素の重要単語リストから成る、テストケース重要単語データを生成する。
    \end{enumerate}
    \item $2$.で生成した全ての要求仕様重要単語データをリスト化し、要求仕様重要単語データリストを生成する。                                                                                                       
    \item $3$.で生成した全てのテストケース重要単語データをリスト化し、テストケース重要単語データリストを生成する。
\end{enumerate}

\subsection{類似度算出処理}\label{subsec:similarity_calculation}
類似度算出処理は、重要単語抽出処理 (\cref{sec:imp_word}節参照) で生成した要求仕様重要単語データリストおよびテストケース重要単語データリストを用いて、
要求仕様とテストケース間の全ての組み合わせにおける類似度を算出する処理である。
具体的には、重要単語抽出処理から受け取った、要求仕様重要単語データリストとテストケース重要単語データリスト、
および、初期設定(\ref{sec:config}節参照)で記述した設定ファイルvitt.yamlの3つを入力とし、対応付け情報リストを出力する。
出力は、対応関係抽出処理(\ref{sec:traceability_extraction_processing}節で後述)に渡す。

対応付け情報リストは、要求仕様とテストケース間の類似度の情報である対応付け情報オブジェクトのリストである。

対応付け情報オブジェクトは、以下に示す6つの情報を持つ。
\begin{itemize}
    \item 要求仕様ID: 要求仕様を一意に識別するID
    \item テストケースID: テストケースを一意に識別するID
    \item 前提条件と事前条件の類似度: 要求仕様の前提条件とテストケースの事前条件のテキスト間の類似度
    \item トリガーと操作の類似度: 要求仕様のトリガーとテストケースの操作のテキスト間の類似度
    \item システム応答と期待出力の類似度: 要求仕様のシステム応答とテストケースの期待出力のテキスト間の類似度
    \item 合計スコア: $3$つの対応付け要素間(\ref{sec:words}節参照)の類似度の重み付け平均
\end{itemize}

本処理では、$2$つのテキスト間の類似度を測る指標としてJaccard係数(\ref{sec:Jaccard}節参照)を使用する。

本処理の流れを、以下に示す。
\begin{enumerate}
    \item 重要単語抽出処理の出力である、要求仕様重要単語データリストとテストケース重要単語データリストを入力として読み込む。
    \item 設定ファイルvitt.yamlのweightsの項目から、以下の3つの対応付け要素の重みの値を取得する。       
    \begin{itemize}                                                                           
        \item $w_{\text{precondition}}$\\
        preconditionに設定した前提条件と事前条件の重み                                          
        \item $w_{\text{trigger\_operation}}$\\
        trigger\_operationに設定したトリガーと操作の重み                                        
        \item $w_{\text{response\_output}}$\\
        response\_outputに設定したシステム応答と期待出力の重み                                  
    \end{itemize}
    \item 空の対応付け情報リストを用意する。
    \item 要求仕様重要単語データリスト内の要求仕様重要単語データとテストケース重要単語データリスト内のテストケース重要単語データの全ての組み合わせにおいて、以下の処理を繰り返す。
    \begin{enumerate}
        \item 要求仕様重要単語データから、要求仕様IDと$3$つの対応付け要素の重要単語リストを抽出する。同様に、テストケース重要単語データから、テストケースIDと$3$つの対応付け要素の重要単語リストを抽出する。
        \item 抽出した重要単語リストから、以下の$3$つの対応付け要素間について、Jaccard係数を用いて類似度を算出する。
        \begin{itemize}
            \item 前提条件と事前条件
            \item トリガーと操作
            \item システム応答と期待出力
        \end{itemize}
        \item $4$.(b)で算出した $3$つの対応付け要素間の類似度に対して、
        $2$.で取得した3つの対応付け要素の重みの値を掛けて合算し、合計スコア$S_{\text{total}}$を算出する。
        合計スコアを算出する式を、\cref{eq:total_score}に示す。

        \begin{equation}
            S_{\text{total}} = w_{\text{precondition}} \cdot S_{\text{pre}} + w_{\text{trigger\_operation}} \cdot S_{\text{trig}} + w_{\text{response\_output}} \cdot S_{\text{resp}}\label{eq:total_score}
        \end{equation}

        ここで、$S_{\text{pre}}$は前提条件と事前条件の類似度、$S_{\text{trig}}$はトリガーと操作の類似度、$S_{\text{resp}}$はシステム応答と期待出力の類似度である。

        \item $4$.(a)で抽出した要求仕様IDとテストケースID、$4$.(b)で算出した各対応付け要素間の類似度、
        および、$4$.(c)で算出した合計スコア$S_{\text{total}}$を対応付け情報オブジェクトとして、
        $3$.で用意した対応付け情報リストの末尾に追加する。
    \end{enumerate}
\end{enumerate}

\subsection{対応関係抽出処理}\label{sec:traceability_extraction_processing}
対応関係抽出処理は、類似度算出処理(\cref{subsec:similarity_calculation}節参照)で生成した対応付け情報リストから、要求仕様とテストケースの対応関係を抽出する処理である。
具体的には、類似度算出処理から受け取った、対応付け情報リストおよび、初期設定(\ref{sec:config}節参照)で記述した設定ファイルvitt.yamlの2つを入力とし、対応関係情報リストを出力する。
出力は、TCVダイアグラム生成部(\cref{sec:diagram-generation}で後述)に渡す。

本処理の流れを、以下に示す。
\begin{enumerate}
    \item 類似度算出処理の出力である、対応付け情報リストを入力として読み込む。
    \item 設定ファイルvitt.yamlのsimilarity\_thresholdの項目から、類似度の閾値を取得する。
    \item 空のリストAを用意する。
    \item 対応付け情報リスト内の対応付け情報オブジェクトの数だけ、以下の処理を繰り返す。
    \begin{enumerate}
        \item 対応付け情報リストの先頭から、未処理の対応付け情報オブジェクトを1つ取り出す。
        \item 取り出した対応付け情報オブジェクトから、合計スコアを取得する。
        \item 取得した合計スコアが、$2$.で取得した類似度の閾値以上であるかを検証する。
        \begin{itemize}
            \item 閾値未満の場合\\
            $4$.(a)の処理に戻り、 対応付け情報リスト内の、次の対応付け情報オブジェクトを処理する。
            \item 閾値以上の場合\\
            $3$.で用意したリストAの末尾に、対応付け情報オブジェクトを追加する。
        \end{itemize}
    \end{enumerate}
    \item $3$.で用意したリストAを、合計スコアの降順にソートする。
    \item 空のリストBを用意する。
    \item $5$.でソートしたリストA内の、対応付け情報オブジェクトの数だけ、以下の処理を繰り返す。
    \begin{enumerate}
        \item リストAの先頭から、未処理の対応付け情報オブジェクトを1つ取り出す。
        \item 取り出した対応付け情報オブジェクトから、要求仕様IDおよびテストケースIDを取得する。
        \item $6$.で用意したリストB内に、$7$.(b)で取得した要求仕様IDまたはテストケースIDを持つ対応付け情報オブジェクトがすでに存在するかを検証する。
        \begin{itemize}
            \item 要求仕様IDまたはテストケースIDが、すでに存在する場合\\
            $7$.(a)の処理に戻り、リストA内の、次の対応付け情報オブジェクトを処理する。
            \item 要求仕様IDおよびテストケースIDが、存在しない場合\\
            取り出した対応付け情報オブジェクトを、$6$.で用意したリストBの末尾に追加する。
        \end{itemize}
    \end{enumerate}
    \item 空のリストCを用意する。
    \item $6$.で用意したリストB内の対応付け情報オブジェクトの数だけ、以下の処理を繰り返す。
    \begin{enumerate}
        \item リストBの先頭から、未処理の対応付け情報オブジェクトを1つ取り出す。
        \item 取り出した対応付け情報オブジェクトから、$3$つの対応付け要素間の類似度(「前提条件」と「事前条件」、「トリガー」と「操作」、「システム応答」と「期待出力」)を取得する。
        \item 取得した3つの類似度が、$2$.で取得した類似度の閾値以上であるかをそれぞれ確認し、閾値以上である類似度の数を数える。
        \item 閾値以上である類似度の数に応じて、品質種別を決定する。
        \begin{itemize}
            \item 閾値以上である類似度の数が$3$つの場合(3つ全てが閾値以上の類似度の場合)\\
            品質種別を\texttt{FULL}とする。
            \item 閾値以上である類似度の数が$1$つまたは$2$つの場合(1つまたは2つが閾値以上の類似度の場合)\\
            品質種別を\texttt{PARTIAL}とする。
        \end{itemize}
        \item 対応付け情報オブジェクトの情報と$9$.(d)で決定した品質種別から、対応関係情報オブジェクトを生成し、$8$.で用意したリストCの末尾に追加する。
    \end{enumerate}
    \item リストCを、対応関係情報リストとして出力する。
\end{enumerate}

        特に、表\ref{tb:reqspec_obj_example}で示した要求仕様情報オブジェクトのparent\_idおよびchildren\_idsプロパティの値を用いて
        生成する、要求仕様の親子関係の実線矢印を表すPlantUMLコードは、図\ref{fig:puml_code}の32行目に該当する。
        \item 要求仕様エリアの終了タグ「\}」を、変数puml\_codeに格納する。
    \end{enumerate}

    \item テストケースエリアの生成
    \begin{enumerate}
        \item テストケースエリアの開始タグ「\{」を、変数puml\_codeに格納する。
        \item テストケース情報リストの要素をtest\_suiteプロパティの値でグループ化し、各グループについて、以下の処理を繰り返す。
        \begin{enumerate}
            \item test\_suiteプロパティの値をテストスイート名として、テストスイートエリアの開始タグ「\{」を、変数puml\_codeに格納する。
            \item グループ内の全てのテストケース情報オブジェクトについて、以下の処理を繰り返す。
            \begin{enumerate}
                \item 対応関係情報リストから、各テストケース情報オブジェクトのidプロパティの値と一致するテストケースIDを持つ対応関係情報オブジェクトを探索する。
                \item 探索結果に応じて、テストケースの矩形要素に対応する背景色を設定する。
                \begin{itemize}
                    \item 該当する対応関係情報オブジェクトが存在しない場合\\
                    背景色に、表\ref{tab:quality_type}に示した「NONE」に対応する赤色を設定する。
                    \item 該当する対応関係情報オブジェクトが存在する場合\\
                    対応関係情報オブジェクトの品質種別に基づき、背景色に、表\ref{tab:quality_type}に示した「FULL」に対応する緑色、または、「PARTIAL」に対応する黄色を設定する。
                \end{itemize}
                \item テストケース情報オブジェクトのid、name、precondition、operation、expected\_outputプロパティの値と、
                $4$.(b)ii.B.で設定した背景色を用いて、テストケースの矩形要素を表すPlantUMLコードを生成し、変数puml\_codeに格納する。
                図\ref{fig:testsuite_example_input_analysis_section}で示した3件のテストケースに対して生成する、テストケースの矩形要素を表すPlantUMLコードは、
                図\ref{fig:puml_code}の38行目から40行目に該当する。
                特に、表\ref{tb:testcase_obj_example}で示したテストケース情報オブジェクトに対して生成する、テストケースの矩形要素を表すPlantUMLコードは、
                図\ref{fig:puml_code}の38行目に該当する。
            \end{enumerate}
            \item テストスイートエリアの終了タグ「\}」を、変数puml\_codeに格納する。
        \end{enumerate}
        \item テストケースエリアの終了タグ「\}」を、変数puml\_codeに格納する。
    \end{enumerate}
    \item 要求仕様エリアとテストケースエリアを生成後、対応関係情報リストに基づき、
    対応関係がある要求仕様の矩形要素とテストケースの矩形要素を、
    合計スコアのラベルを付与した破線で結ぶPlantUMLコードを生成し、変数puml\_codeに格納する。
    図\ref{fig:tcv_diagram_example}で示した、対応関係がある要求仕様ID「REQ-1-1」の矩形要素とテストケースID「TC-1」の矩形要素、および、
    要求仕様ID「REQ-1-3」の矩形要素とテストケースID「TC-3」の矩形要素に対して
    生成する、合計スコアのラベルを付与した破線で結ぶPlantUMLコードは、
    図\ref{fig:puml_code}の43行目、および、44行目に該当する。
    \item PlantUML終了タグ「@enduml\textbackslash n」を、変数puml\_codeに格納する。
    図\ref{fig:puml_code}の45行目が、ここで格納するPlantUMLコードに該当する。
    \item 変数puml\_codeをPlantUMLコードとして、TCVダイアグラム出力処理に渡す。
\end{enumerate}

\subsection{TCVダイアグラム出力処理}\label{subsec:diagram-generation-process}
TCVダイアグラム出力処理は、PlantUMLコード生成処理(\ref{subsec:puml-generation}節参照)で生成したPlantUMLコードから、TCVダイアグラムを出力する処理である。
具体的には、PlantUMLコード生成処理で生成したPlantUML コードを入力とし、TCV ダイアグラムをローカルサーバーを介して配信する。
なお、ユーザーは、任意のWebブラウザを立ち上げて、そのブラウザ上でURL「http://localhost:8000」にアクセスすることで、TCVダイアグラムを確認できる。

本処理の流れを、以下に示す。
\begin{enumerate}
    \item PlantUMLコード生成処理の出力であるPlantUMLコードを、入力として読み込む。
    \item PlantUMLコードを.pumlファイルとして保存する。
    \item PlantUMLライブラリ(\ref{sec:PlantUML}節参照)を用いて、.pumlファイルからSVG (Scalable Vector Graphics) 形式にしたTCVダイアグラムを生成する。
    \item http.serverモジュール(\cref{sec:Python}参照)を用いてローカルサーバーを起動し、SVG形式にしたTCVダイアグラムを配信する。
\end{enumerate}
