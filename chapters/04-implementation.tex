% 入力解析部
\section{入力解析部}\label{sec:input-data-analysis}
入力解析部は、要求仕様書およびテストケースを解析し、処理部間のやり取りに用いる中間データとして、要求仕様に関する情報を保持したオブジェクトとテストケースに関する情報を保持したオブジェクトのリストに変換する処理部である。

本処理部は、入力として要求仕様書およびテストケースを受け取り、要求仕様情報リストとテストケース情報リストを出力とする。
出力は、対応関係分析部(\ref{sec:correspondence-analysis}節で後述)および出力図生成部(\ref{sec:diagram-generation}節で後述)に渡す。

入力解析部では、以下の$2$つの処理を行う。
\begin{itemize}
    \item 要求仕様情報リスト生成処理
    \item テストケース情報リスト生成処理
\end{itemize}
以降、それぞれの処理について説明する。

\subsection{要求仕様情報リスト生成処理}\label{subsec:req_extraction}
要求仕様情報リスト生成処理は、CSV形式で記述した要求仕様書を読み込み、処理部間のやり取りに用いる要求仕様情報オブジェクトのリストを生成する処理である。
本処理は、CSV形式の要求仕様書を入力とし、要求仕様情報リストを出力とする。
本処理が入力として受け取る要求仕様書の例を、図\ref{fig:sample_text}に示す。

要求仕様情報オブジェクトは、要求仕様書の各要求仕様に関する情報を格納したオブジェクトであり、以下に示す$10$個のプロパティを持つ。

\begin{itemize}
    \item 要求仕様情報オブジェクト
    \begin{itemize}
        \item id: 要求仕様IDを表す文字列
        \item name: 要求仕様の名称を表す文字列
        \item description: 要求仕様テンプレートの内容を表す文字列
        \item precondition: 前提条件の内容を表す文字列
        \item trigger: トリガーの内容を表す文字列
        \item system: システム名を表す文字列
        \item response: システム応答の内容を表す文字列
        \item parent\_id: 親要求仕様IDを表す文字列
        \item children\_ids: 子要求仕様IDを表す文字列を格納するリスト
        \item is\_traceable: テストケースと対応付け可能かどうかを示す真偽値
    \end{itemize}
\end{itemize}

\begin{figure}[tp]
    \centering
    \fbox{
        \includegraphics[width=0.96\textwidth]{images/sample_text.png}
        }
        \caption{入力とする要求仕様書の例}
        \label{fig:sample_text}
    \end{figure}

本処理は、以下の4つの処理を順に実行し、要求仕様情報リストを生成する。
\begin{itemize}
    \item 要求仕様記述項目抽出処理
    \item 要求仕様テンプレート生成処理
    \item 対応付け可否判定処理
    \item 階層関係抽出処理
\end{itemize}

以降、それぞれの処理について説明する。

\subsubsection{要求仕様記述項目抽出処理}\label{subsubsec:req_item_extraction}
要求仕様記述項目抽出処理は、要求仕様書の各要求仕様から、要求仕様記述項目 (\cref{tb:reqspec_item}参照)の情報を抽出する処理である。
本処理は、CSV形式で記述した要求仕様書を入力とし、要求仕様記述項目と対応する要求仕様情報オブジェクトのプロパティに値を代入した要求仕様情報オブジェクトのリストを出力とする。

本処理の流れを以下に示す。
\begin{enumerate}
    \item 空の要求仕様情報オブジェクトのリストを用意する。\label{enum:空要求仕様情報リスト}
    \item CSV形式の要求仕様書を読み込む。
    \item DictReader関数(\ref{sec:Python}節を参照)を用いて、CSVの1行目をヘッダー行 ("要求仕様ID","要求仕様名","前提条件","トリガー","システム名","システム応答") とし、2行目以降の各データ行をヘッダー行をキーとした辞書形式で読み込む。
    \item 2行目以降の各データ行について、以下の処理を繰り返す。
    \begin{enumerate}
        \item ヘッダー行の各キーに対応する値を取得する。
        \item 要求仕様情報オブジェクトを生成し、取得した値を以下のように、要求仕様情報オブジェクトの各プロパティに代入する。
        \begin{itemize}
            \item idプロパティに"要求仕様ID"をキーとした値を代入する
            \item nameプロパティに"要求仕様名"をキーとした値を代入する
            \item preconditionプロパティに"前提条件"をキーとした値を代入する
            \item triggerプロパティに"トリガー"をキーとした値を代入する
            \item systemプロパティに"システム名"をキーとした値を代入する
            \begin{itemize}
                \item "システム名"をキーとした値が空文字列の場合\\
                初期設定 (\cref{sec:config}参照) で記述した設定ファイルvitt.yamlのsystem\_nameの値を代入する。
            \end{itemize}
            \item responseプロパティに"システム応答"をキーとした値を代入する
        \end{itemize}
        \item 生成した要求仕様情報オブジェクトを、\cref{enum:空要求仕様情報リスト}で用意したリストに追加する。
    \end{enumerate}
\end{enumerate}

\subsubsection{要求仕様テンプレート生成処理}\label{subsubsec:req_text_gen}
要求仕様テンプレート生成処理は、要求仕様記述項目抽出処理で抽出した、要求仕様オブジェクトのprecondition、trigger、system、responseの各プロパティの文字列を組み合わせ、要求仕様テンプレート(\cref{sec:EARS}参照)を生成する処理である。
本処理は、要求仕様記述項目抽出処理で生成した要求仕様情報オブジェクトのリストを入力とし、要求仕様テンプレートを表すdescriptionプロパティに値を代入した要求仕様情報オブジェクトのリストを出力とする。
本処理の目的は、要求仕様テンプレートを出力図に表示して、各要求仕様の内容の把握を容易にすることである。

要求仕様テンプレート生成処理の流れを以下に示す。
\begin{enumerate}
    \item 要求仕様情報オブジェクトのリスト内の各オブジェクトに対して、以下の処理を繰り返す。
    \begin{enumerate}
        \item 要求仕様テンプレートの部分文字列を格納する空のリストを用意する。
        \item 要求仕様情報オブジェクトからprecondition、trigger、system、responseの各プロパティの値を取得する。
        \item 取得した各プロパティの値に応じて、以下の処理を行う。
        \begin{itemize}
            \item preconditionプロパティの値が空文字列でない場合\\
            "\{precondition\}場合"という形式の部分文字列をリストに追加する。
            \item triggerプロパティの値が空文字列でない場合\\
            "\{trigger\}時"という形式の部分文字列をリストに追加する。
            \item systemプロパティとresponseプロパティの値が両方とも空文字列でない場合\\
            "\{system\}は\{response\}べきである"という形式の部分文字列をリストに追加する。
        \end{itemize}
        \item リスト内の部分文字列を読点（、）で結合し、要求仕様テンプレートを生成する。
        \item 生成した要求仕様テンプレートを、要求仕様情報オブジェクトのdescriptionプロパティに代入する。
    \end{enumerate}    
\end{enumerate}

\subsubsection{対応付け可否判定処理}\label{subsubsec:req_traceability}
対応付け可否判定処理は、各要求仕様がテストケースとの対応付けを行う対象となるかを判定する処理である。
本処理は、要求仕様テンプレート生成処理で生成した要求仕様情報オブジェクトのリストを入力とし、テストケースと対応付け可能かどうかを示すis\_traceableプロパティに値を代入した要求仕様情報オブジェクトのリストを出力とする。
本研究では、\cref{tb:traceability}で示す、要求仕様の対応付け要素 (「前提条件」、「トリガー」、「システム応答」)とテストケースの対応付け要素 (「事前条件」、「入力・操作」、「期待出力」)のそれぞれのテキスト間の類似度を算出し、要求仕様とテストケースの対応関係を抽出する。
そのため、要求仕様の対応付け要素のうち、いずれか$1$つでも対応付け要素の値が空文字列である要求仕様は、テストケースとの対応付けの対象外とする。

本処理の流れを、以下に示す。
\begin{enumerate}
    \item 要求仕様情報オブジェクトのリスト内の各オブジェクトに対して、以下の処理を繰り返す。
    \begin{enumerate}
        \item 要求仕様情報オブジェクトのprecondition、trigger、responseの3つのプロパティの値を取得する。
        \item 取得した3つのプロパティの値によって処理を分岐する。
        \begin{itemize}
            \item 3つのプロパティの値が全て空文字列でない場合\\
            テストケースとの対応付け可能な要求仕様と判定し、is\_traceableプロパティにtrueを代入する。
        \end{itemize}
        \begin{itemize}
            \item 3つのプロパティのうち、いずれか1つのプロパティの値が空文字列であった場合\\
            テストケースとの対応付け可能ではない要求仕様と判定し、is\_traceableプロパティにfalseを代入する。
        \end{itemize}
    \end{enumerate}
\end{enumerate}

\subsubsection{階層関係抽出処理}\label{subsubsec:req_hierarchy}
階層関係抽出処理は、要求仕様IDの命名規則 (\ref{sec:reqspec}節参照) に基づき、要求仕様間の親子関係の情報を抽出する処理である。
本処理は、対応付け可否判定処理で生成した要求仕様情報オブジェクトのリストを入力とし、parent\_idおよびchildren\_idsプロパティに値を代入した要求仕様情報リストを出力とする。
出力は、対応関係分析部(\ref{sec:correspondence-analysis}節で後述)および出力図生成部(\ref{sec:diagram-generation}節で後述)に渡す。
階層関係抽出の例を、表\ref{tb:hierarchy_example}に示す。

本処理の流れを、以下に示す。
\begin{enumerate}
    \item 要求仕様情報オブジェクトのidプロパティの値をキーとし、要求仕様情報オブジェクト自体を値とする辞書を作成する。
    \item 要求仕様情報オブジェクトのリストを、idプロパティの値の辞書順でソートする。
    \item ソートした要求仕様情報オブジェクトのリストにある要求仕様情報オブジェクトの数だけ、以下の処理を繰り返す。
    \begin{enumerate}
        \item 要求仕様情報オブジェクトのリストより、要求仕様情報オブジェクトを1つ取得する。\label{enum:要求仕様情報オブジェクト取得}
        \item \ref{enum:要求仕様情報オブジェクト取得}で取得した要求仕様情報オブジェクトのidプロパティの値をハイフン('-')で分割し、分割結果の要素数を確認する。
        \item 分割結果の要素数に応じて、以下の処理を行う。
        \begin{itemize}
            \item 要素数が2個の場合 (例:"REQ-1" の場合、分割結果["REQ" , "1"])\\
            親要求仕様を持たない要求仕様情報オブジェクトのため、次の要求仕様情報オブジェクトの処理に移る。
            \item 要素数が3個以上の場合 (例:"REQ-1-1-2" の場合、分割結果["REQ" , "1" , "1", "2"])\\
            親要求仕様を持つ子要求仕様オブジェクトのため、以下の処理を行う。
            \begin{enumerate}
                \item 分割結果の末尾要素を除いた部分をハイフンで結合し、親要求仕様のidプロパティの値を生成する。
                例として、idプロパティの値が "REQ-1-1-2" の場合、分割結果["REQ" , "1" , "1", "2"]のうち、末尾の "2" を除いた[ "REQ" , "1", "1"]を結合し、親要求仕様のidプロパティの値 "REQ-1-1" を生成する。
                \item 生成した親要求仕様のidプロパティの値をキーとして、辞書から対応する親要求仕様情報オブジェクトを取得する。
                \item 取得した親要求仕様情報オブジェクトと\ref{enum:要求仕様情報オブジェクト取得}で取得した子要求仕様情報オブジェクトの間に、親子関係を双方向に記録する。
                具体的には、子要求仕様情報オブジェクトのparent\_idプロパティに親要求仕様情報オブジェクトのidプロパティの値を代入し、親要求仕様情報オブジェクトのchildren\_idsリストに子要求仕様情報オブジェクトのidプロパティの値を追加する。
            \end{enumerate}
        \end{itemize}
    \end{enumerate}
\end{enumerate}

\subsection{テストケース情報リスト生成処理}\label{sec:testcase-data-extraction}
テストケース情報リスト生成処理は、CSV形式で記述したテストケースを読み込み、処理部間のやり取りに用いるテストケース情報オブジェクトのリストを生成する処理である。
本処理は、CSV形式のテストケースを入力とし、テストケース情報リストを出力とする。本処理が入力として受け取るテストケースの例を、図\ref{fig:testcase_sample2}に示す。

テストケース情報オブジェクトは、各テストケースに関する情報を格納したオブジェクトであり、以下に示す$6$個のプロパティを持つ。

\begin{itemize}
    \item テストケース情報オブジェクト
    \begin{itemize}
        \item id: テストケースIDを表す文字列
        \item name: テストケースの名称を表す文字列
        \item precondition: 事前条件の内容を表す文字列
        \item operation: 入力・操作の内容を表す文字列
        \item expected\_output: 期待出力の内容を表す文字列
        \item test\_suite: ファイル名から抽出したテストスイートの名称を表す文字列
    \end{itemize}
\end{itemize}

\begin{figure}[tp]
    \centering
    \fbox{
        \includegraphics[width=0.96\textwidth]{images/testcase_sample2.png}
        }
        \caption{入力とするテストケースの例}
        \label{fig:testcase_sample2}
    \end{figure}

本処理の流れを、以下に示す。

\begin{enumerate}
    \item 空のテストケース情報オブジェクトのリストを用意する。\label{enum:空テストケース情報リスト}
    \item CSV形式のテストケースの数だけ、以下の処理を繰り返す。
    \begin{enumerate}
        \item CSV形式のテストケースを1つ取得する。
        \item 取得したCSVファイル名から拡張子(.csv)を除去し、テストスイート名として保持する。
        例えば、ファイル名が「ログインテスト.csv」の場合、「ログインテスト」をテストスイート名として保持する。
        \item CSVファイルを読み込む。
        \item DictReader関数(\ref{sec:Python}節を参照)を用いて、CSVの1行目をヘッダー行 ("テストケースID", "テストケース名", "事前条件", "入力・操作", "期待出力")とし、2行目以降の各データ行をヘッダー行をキーとした辞書形式で読み込む。
        \item 2行目以降の各データ行について、以下の処理を繰り返す。
        \begin{enumerate}
            \item ヘッダー行の各キーに対応する値を取得する。
            \item テストケース情報オブジェクトを生成し、取得した値を以下のように、テストケース情報オブジェクトの各プロパティに代入する。
            \begin{itemize}
                \item idプロパティに"テストケースID"をキーとした値を代入する
                \item nameプロパティに"テストケース名"をキーとした値を代入する
                \item preconditionプロパティに"事前条件"をキーとした値を代入する
                \item operationプロパティに"入力・操作"をキーとした値を代入する
                \item expected\_outputプロパティに"期待出力"をキーとした値を代入する
                \item test\_suiteプロパティに保持しているテストスイート名を代入する
            \end{itemize}
            \item 生成したテストケース情報オブジェクトを、\cref{enum:空テストケース情報リスト}で用意したリストに追加する。
        \end{enumerate}
    \end{enumerate}
\end{enumerate}

% 対応関係分析部
\section{対応関係分析部}\label{sec:correspondence-analysis}
対応関係分析部は、入力解析部(\ref{sec:input-data-analysis}節参照)で生成した要求仕様情報リストとテストケース情報リストを分析し、要求仕様とテストケース間の対応関係を抽出する処理部である。
本処理部は、入力として要求仕様情報リストとテストケース情報リストを受け取り、対応関係情報リストを出力とする。
出力は、出力図生成部(\ref{sec:diagram-generation}節で後述)に渡す。

対応関係分析部では、以下の$4$つの処理を行う。
\begin{itemize}
    \item 形態素解析処理(\cref{sec:morphological_analysis}節で後述)
    \item 重要単語抽出処理(\cref{sec:imp_word}節で後述)
    \item 類似度算出処理(\cref{subsec:similarity_calculation}節で後述)
    \item 対応関係抽出処理(\cref{sec:traceability_extraction_processing}節で後述)
\end{itemize}
以降、それぞれの処理について説明する。

\subsection{形態素解析処理}\label{sec:morphological_analysis}
形態素解析処理は、要求仕様情報リストとテストケース情報リストに含まれる対応付け要素の文字列を、MeCab (\cref{sec:Mecab}参照)を用いて形態素に分割し、品詞情報と基本形を取得する処理である。
本処理は、要求仕様情報リストとテストケース情報リストを入力とし、要求仕様形態素データリストおよびテストケース形態素データリストを出力する。
出力は、重要単語抽出処理(\ref{sec:imp_word}節で後述)に渡す。

要求仕様形態素データは、以下に示す$4$つの情報を持つ。
本研究では、形態素情報は、各形態素の品詞と基本形からなる情報のことを表す。
\begin{itemize}
    \item 要求仕様形態素データ
    \begin{itemize}
        \item 要求仕様ID: 要求仕様を一意に識別するID。
        \item 前提条件の形態素情報リスト: 前提条件の文字列を形態素に分割し、各形態素の品詞と基本形の対を保持したリスト。
        \item トリガーの形態素情報リスト: トリガーの文字列を形態素に分割し、各形態素の品詞と基本形の対を保持したリスト。
        \item システム応答の形態素情報リスト: システム応答の文字列を形態素に分割し、各形態素の品詞と基本形の対を保持したリスト。
    \end{itemize}
\end{itemize}

テストケース形態素データは、以下に示す$4$つの情報を持つ。
\begin{itemize}
    \item テストケース形態素データ
    \begin{itemize}
        \item テストケースID: テストケースを一意に識別するID。
        \item 事前条件の形態素情報リスト: 事前条件の文字列を形態素に分割し、各形態素の品詞と基本形の対を保持したリスト。
        \item 入力・操作の形態素情報リスト: 入力・操作の文字列を形態素に分割し、各形態素の品詞と基本形の対を保持したリスト。
        \item 期待出力の形態素情報リスト: 期待出力の文字列を形態素に分割し、各形態素の品詞と基本形の対を保持したリスト。
    \end{itemize}
\end{itemize}

本処理の流れを、以下に示す。
\begin{enumerate}
    \item 入力解析部 (\cref{sec:input-data-analysis}) の出力である、要求仕様情報リストとテストケース情報を入力として読み込む。
    \item 要求仕様形態素データの生成\\
    要求仕様情報リストが持つ要求仕様オブジェクトの数だけ、以下の処理を繰り返す。
    \begin{enumerate}
        \item 要求仕様情報リストから、要求仕様オブジェクトを$1$つ取り出す。
        \item 取り出した要求仕様オブジェクトが対応付け可能要求仕様でない場合（is\_traceableプロパティの値がfalse）\\
            形態素解析処理を行わず、$1$.(a)の処理に戻る。
        \item 取り出した要求仕様オブジェクトから、要求仕様IDおよび$3$つの対応付け要素（前提条件、トリガー、システム応答）の文字列を抽出する。
        \item 抽出した$3$つの対応付け要素の文字列それぞれについて、以下の処理を実行する。
        \begin{enumerate}
            \item 全角英数字を半角英数字に変換する前処理を行う。\\
            これは、「３」と「3」、「Ａ」と「A」のような表記揺れを統一し、類似度算出処理(\cref{subsec:similarity_calculation}節で後述) での精度を向上させる目的がある。
            \item MeCabを用いて、前処理後の文字列を形態素に分割し、品詞と基本形を抽出する。\\
            ここで、基本形が取得できない未知語の場合、表層形を基本形として使用する。
            \item 抽出した品詞と基本形の対を形態素情報として、形態素情報リストに追加する。
        \end{enumerate}
        \item 要求仕様IDと$3$つの対応付け要素の形態素情報リストを結合し、$1$つの要求仕様形態素データとして保持する。
    \end{enumerate}
    \item テストケース形態素データの生成\\
    テストケース情報リストが持つテストケースオブジェクトの数だけ、以下の処理を繰り返す。
    \begin{enumerate}
        \item テストケース情報リストから、テストケースオブジェクトを$1$つ取り出す。
        \item 取り出したテストケースオブジェクトから、テストケースIDおよび$3$つの対応付け要素（事前条件、入力・操作、期待出力）の文字列を抽出する。
        \item 抽出した$3$つの対応付け要素の文字列それぞれについて、$2$.(d)と同様の処理を実行する。
        \item テストケースIDと$3$つの対応付け要素の形態素情報リストを結合し、$1$つのテストケース形態素データとして保持する。
    \end{enumerate}
    \item $2$.で生成した全要求仕様形態素データ と $3$.で生成した全テストケース形態素データをそれぞれリスト化し、要求仕様形態素データリストおよびテストケース形態素データリストを生成する。
\end{enumerate}

\subsection{重要単語抽出処理}\label{sec:imp_word}
重要単語抽出処理は、形態素解析処理(\cref{sec:morphological_analysis}節参照)で生成した要求仕様形態素データリストおよびテストケース形態素データリストから、重要単語を抽出する処理である。
本処理は、要求仕様形態素データリストとテストケース形態素データリストを入力とし、要求仕様重要単語データリストおよびテストケース重要単語データリストを出力する。
出力は、類似度算出処理(\ref{subsec:similarity_calculation}節で後述)に渡す。

本研究では、重要単語として名詞、動詞、複合名詞を抽出する。
名詞は要求仕様やテストケースにおいて、対象物や概念を表し、動詞はシステムの動作や振る舞いを表すため、対応付けにおいて重要な意味を持つ。
また、複合名詞は連続する名詞または連続する接頭辞と名詞、と定義し、単独の名詞よりも要求仕様やテストケースの内容を具体的に表すことができるため抽出する。

要求仕様重要単語データは、以下に示す$4$つの情報を持つ。
\begin{itemize}
    \item 要求仕様重要単語データ
    \begin{itemize}
        \item 要求仕様ID: 要求仕様を一意に識別するID。
        \item 前提条件の重要単語リスト: 前提条件の形態素情報リストから抽出した名詞、動詞、複合名詞を結合したリスト
        \item トリガーの重要単語リスト: トリガーの形態素情報リストから抽出した名詞、動詞、複合名詞を結合したリスト
        \item システム応答の重要単語リスト: システム応答の形態素情報リストから抽出した名詞、動詞、複合名詞を結合したリスト
    \end{itemize}
\end{itemize}

テストケース重要単語データは、以下に示す$4$つの情報を持つ。
\begin{itemize}
    \item テストケース重要単語データ
    \begin{itemize}
        \item テストケースID: テストケースを一意に識別するID。
        \item 事前条件の重要単語リスト: 事前条件の形態素情報リストから抽出した名詞、動詞、複合名詞を結合したリスト
        \item 入力・操作の重要単語リスト: 入力・操作の形態素情報リストから抽出した名詞、動詞、複合名詞を結合したリスト
        \item 期待出力の重要単語リスト: 期待出力の形態素情報リストから抽出した名詞、動詞、複合名詞を結合したリスト
    \end{itemize}
\end{itemize}

本処理の流れを、以下に示す。
\begin{enumerate}
    \item 形態素解析処理 (\cref{sec:morphological_analysis}節参照) の出力である、要求仕様形態素データリストとテストケース形態素データリストを入力として読み込む。
    \item 要求仕様重要単語データの生成\\
    要求仕様形態素データリストが持つ要求仕様形態素データの数だけ、以下の処理を繰り返す。
    \begin{enumerate}
        \item 要求仕様形態素データリストから、要求仕様形態素データを$1$つ取り出す。
        \item 取り出した要求仕様形態素データから、$3$つの対応付け要素の形態素情報リストを抽出する。
        \item 抽出した$3$つの対応付け要素の形態素情報リストそれぞれについて、以下の処理を実行する。
        \begin{enumerate}
            \item 名詞と動詞の抽出\label{enum:品詞別キーワード抽出}\\
            品詞が名詞または動詞である形態素を抽出し、抽出した名詞を名詞リストに、動詞を動詞リストに追加する。
            ここで、基本形が記号のみで構成されている形態素は、重要単語として扱わないため除外する。

            \item 複合名詞の抽出\label{enum:複合名詞抽出}\\
            形態素情報リストを先頭から順に走査し、連続する名詞、または、連続する接頭辞と名詞を結合した複合名詞を生成する。

            \item 複合名詞の妥当性判定\label{enum:妥当性判定}\\
            生成した複合名詞に対して、以下の条件を全て満たす場合、妥当な複合名詞と判定し、複合名詞リストに追加する。
            \begin{itemize}
                \item 文字数が$3$文字以上$20$文字以下である\\
                $3$文字未満の複合名詞は、単独の名詞と区別しにくいため除外する。
                $20$文字を超える複合名詞は、異常に長い文字列として除外する。
                \item 同じ文字の繰り返しでない\\
                例えば、「あああ」のように同一文字の繰り返しは、形態素解析の誤りである可能性が高いため除外する。
            \end{itemize}

            \item 複合名詞構成要素の除外\\
            名詞リストの各単語について、複合名詞の部分文字列として含まれる単語を、名詞リストから除外する。
            例えば、複合名詞「ログインボタン」が存在する場合、名詞「ログイン」と名詞「ボタン」を名詞リストから除外する。

            \item 重要単語リストの結合\\
            複合名詞構成要素を除外した名詞リスト、動詞リスト、複合名詞リストを結合し、対応付け要素の重要単語リストとして保持する。
        \end{enumerate}
        \item $3$つの対応付け要素の重要単語リストを結合し、$1$つの要求仕様重要単語データとして保持する。
    \end{enumerate}

    \item テストケース重要単語リストの生成\\
    テストケース形態素データリストが持つテストケース形態素データの数だけ、以下の処理を繰り返す。
    \begin{enumerate}
        \item テストケース形態素データリストから、テストケース形態素データを$1$つ取り出す。
        \item 取り出したテストケース形態素データから、$3$つの対応付け要素の形態素情報リストを抽出する
        \item $2$.(c)と同様の処理を実行する。
        \item $3$つの対応付け要素の重要単語リストを結合し、$1$つのテストケース重要単語データとして保持する。
    \end{enumerate}
    \item $2$.で生成した全要求仕様重要単語データ と $3$.で生成した全テストケース重要単語データをそれぞれリスト化し、要求仕様重要単語データリストとテストケース重要単語データリストを生成する。
\end{enumerate}

\subsection{類似度算出処理}\label{subsec:similarity_calculation}
類似度算出処理は、重要単語抽出処理 (\cref{sec:imp_word}節参照) で生成した要求仕様重要単語データリストおよびテストケース重要単語データリストを用いて、全ての要求仕様とテストケースの組み合わせで類似度を算出する処理である。
本処理は、要求仕様重要単語データリストとテストケース重要単語データリストを入力とし、対応付け情報リストを出力とする。
出力は、対応関係抽出処理(\ref{sec:traceability_extraction_processing}節で後述)に渡す。

対応付け情報リストは、以下に示す$4$つの情報を持つ。
\begin{itemize}
    \item 対応付け情報リスト
    \begin{itemize}
        \item 要求仕様ID: 要求仕様を一意に識別するID。
        \item テストケースID: テストケースを一意に識別するID。
        \item 合計スコア: $3$つの対応付け要素間の類似度の重み付け平均。
        \item 各対応付け要素間の類似度: 前提条件と事前条件、トリガーと入力・操作、システム応答と期待出力の類似度。
    \end{itemize}
\end{itemize}

本処理では、$2$つのテキスト間の類似度を測る指標としてJaccard係数(\ref{sec:Jaccard}節参照)を使用する。

本処理の流れを、以下に示す。
\begin{enumerate}
    \item 重要単語抽出処理 (\cref{sec:imp_word}節参照) の出力である、要求仕様重要単語データリストとテストケース重要単語データリストを入力として読み込む。
    \item 全ての要求仕様重要単語データとテストケース重要単語データの組み合わせについて、以下の処理を繰り返す。
    \begin{enumerate}
        \item 要求仕様重要単語データとテストケース重要単語データから、それぞれ$3$つの対応付け要素の重要単語リストを抽出する。
        \item 抽出した$3$つの対応付け要素間それぞれについて、Jaccard係数を用いて類似度を算出する。
        \item $3$つの対応付け要素間の類似度に対して、初期設定(\cref{sec:config}参照)で設定した重みを掛け、合計スコアを算出する。
        \item 要求仕様ID、テストケースID、合計スコア、各対応付け要素間の類似度を記録した対応付け情報をリストに追加する。
    \end{enumerate}
\end{enumerate}

\subsection{対応関係抽出処理}\label{sec:traceability_extraction_processing}
対応関係抽出処理は、類似度算出処理(\cref{subsec:similarity_calculation}節参照)で生成した対応付け情報リストから、要求仕様とテストケースの対応関係を抽出する処理である。
本処理は、対応付け情報リストを入力とし、対応関係情報リストを出力とする。
出力は、出力図生成部(\cref{sec:diagram-generation}節参照)に渡す。

本研究では、対応関係がある要求仕様とテストケースの組に対して、対応関係の十分性を表す指標として品質種別を定義する。
品質種別は、要求仕様とテストケースの3つの対応付け要素間の類似度と閾値に基づいて判定する。
品質種別には、以下に示す、すべての対応付け要素間の類似度が閾値以上であることを表す\texttt{FULL} (全一致) と、一部の対応付け要素間の類似度のみが閾値以上であることを表す\texttt{PARTIAL} (部分一致)が存在する。

\begin{itemize}
    \item \texttt{FULL}: 前提条件と事前条件，トリガーと入力・操作，システム応答と期待出力の$3$つ全ての類似度が閾値以上\\
    要求仕様の内容に対して、テストケースの検証内容が十分に対応していることを表す
    \item \texttt{PARTIAL}: 前提条件と事前条件，トリガーと入力・操作，システム応答と期待出力の$3$つのうち、$1$つまたは$2$つの類似度が閾値以上\\
    要求仕様の内容に対して、テストケースの検証内容が一部のみ対応し、テストケースの不備があることを表す。
\end{itemize}

対応関係情報リストは、以下に示す$5$つの情報を持つ。
\begin{itemize}
    \item 対応関係情報リスト
    \begin{itemize}
        \item 要求仕様ID: 要求仕様を一意に識別するID
        \item テストケースID: テストケースを一意に識別するID
        \item 合計スコア: 各$3$つの対応付け要素間の類似度の重み付け平均
        \item 各対応付け要素間の類似度: 前提条件と事前条件、トリガーと入力・操作、システム応答と期待出力の類似度
        \item 品質種別: 対応関係の十分性を示す\texttt{FULL} または \texttt{PARTIAL}
    \end{itemize}
\end{itemize}

本処理の流れを、以下に示す。
\begin{enumerate}
    \item 類似度算出処理 (\cref{subsec:similarity_calculation}節参照) の出力である、対応付け情報リストを入力として読み込む。
    \item 閾値判定とソート\\
    対応付け情報リストから、合計スコアが初期設定(\cref{sec:config}参照)で設定した閾値以上である対応付け情報のみを抽出し、合計スコアの高い順に並び替える。
    これにより、類似度の低い組を除外し、より類似度の高い組を優先的に選択できるようにする。
    \item 双方向$1$対$1$対応関係の抽出 (TODO:対応関係抽出機能(\cref{sec:traceability_extraction_func})で、本研究では、要求仕様とテストケースの対応関係は1対1で抽出することを前提としていることを説明する)\\
    各要求仕様と各テストケースが最大$1$件の対応関係のみを持つように、対応関係を抽出する。
    具体的には、ソート後の対応付け情報を先頭から順に走査し、まだ選択されていない要求仕様とテストケースの組のみを対応関係として採用する。
    これにより、$1$つの要求仕様が複数のテストケースに対応する場合、最も類似度の高いテストケースとのみ対応関係を生成する。
    同様に、$1$つのテストケースが複数の要求仕様に対応する場合、最も類似度の高い要求仕様とのみ対応関係を生成する。
    \item 品質種別の判定\\
    抽出した各対応関係について、$3$つの対応付け要素間の類似度が閾値以上であるかを確認し、品質種別を判定する。
    $3$つ全ての類似度が閾値以上である場合は\texttt{FULL}、$1$つまたは$2$つの類似度が閾値以上である場合は\texttt{PARTIAL}と判定する。
    \item 対応関係情報リストを、出力図生成部(\ref{sec:diagram-generation}節参照)に渡す。
  \end{enumerate}
