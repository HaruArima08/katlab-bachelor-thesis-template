\subsection{要求仕様情報リスト生成処理}\label{subsec:req_extraction}
要求仕様情報リスト生成処理は、CSV形式で記述した要求仕様書を読み込み、処理部間のやり取りに用いる、要求仕様情報リストを生成する処理である。
本処理は、CSV形式の要求仕様書を入力とし、要求仕様情報リストを出力とする。
本処理が入力として受け取る要求仕様書の例を、図\ref{fig:sample_text}に示す。

\begin{figure}[tp]
    \centering
    \fbox{
        \includegraphics[width=0.96\textwidth]{images/sample_text.png}
        }
        \caption{入力とする要求仕様書の例}
        \label{fig:sample_text}
    \end{figure}

本処理は、以下の4つの処理を順に実行し、要求仕様情報リストを生成する。
\begin{itemize}
    \item 要求仕様記述項目抽出処理
    \item 要求仕様テンプレート生成処理
    \item 対応付け可否判定処理
    \item 階層関係抽出処理
\end{itemize}

以降、それぞれの処理について説明する。

\subsubsection{要求仕様記述項目抽出処理}\label{subsubsec:req_item_extraction}
要求仕様記述項目抽出処理は、要求仕様書の各要求仕様から、要求仕様記述項目 (\cref{tb:reqspec_item}参照)の情報を抽出する処理である。
本処理は、CSV形式で記述した要求仕様書を入力とし、要求仕様記述項目と対応する要求仕様情報オブジェクトのプロパティに値を代入した要求仕様情報オブジェクトのリストを出力とする。

本処理の流れを、以下に示す。
\begin{enumerate}
    \item 空のリストを用意する。
    \item CSV形式の要求仕様書を、DictReader関数(\ref{sec:Python}節を参照)を用いて読み込む\\
    CSVの1行目をヘッダー行 (要求仕様ID,要求仕様名,前提条件,トリガー,システム名,システム応答) とし、2行目以降の各データ行を、ヘッダー行のカラム名をキーとした辞書形式で取得する。
    \item 各データ行について、以下の処理を繰り返す。
    \begin{enumerate}
        \item 要求仕様情報オブジェクトを生成し、辞書のキーに対応する値を、要求仕様情報オブジェクトの各プロパティに代入する。
        \begin{itemize}
            \item idプロパティに``要求仕様ID''をキーとした値を代入する。
            \item nameプロパティに``要求仕様名''をキーとした値を代入する。
            \item preconditionプロパティに``前提条件''をキーとした値を代入する。
            \item triggerプロパティに``トリガー''をキーとした値を代入する。
            \item systemプロパティに``システム名''をキーとした値を代入する。\\
            ただし、``システム名''をキーとした値が空文字列の場合、初期設定 (\cref{sec:config}参照) で記述した設定ファイルvitt.yamlのsystem\_nameの値を代入する。
            \item responseプロパティに``システム応答''をキーとした値を代入する。
        \end{itemize}
        \item 生成した要求仕様情報オブジェクトを、$1$. で用意したリストに追加する。
    \end{enumerate}
\end{enumerate}

\subsubsection{要求仕様テンプレート生成処理}\label{subsubsec:req_text_gen}
要求仕様テンプレート生成処理は、要求仕様記述項目抽出処理で生成した、要求仕様オブジェクトのprecondition、trigger、system、responseの各プロパティの文字列を組み合わせ、要求仕様テンプレートを生成する処理である。
本処理は、要求仕様記述項目抽出処理で生成した要求仕様情報オブジェクトのリストを入力とし、要求仕様テンプレートを表すdescriptionプロパティに値を代入した要求仕様情報オブジェクトのリストを出力とする。
本処理の目的は、要求仕様テンプレートを対応関係図に表示して、各要求仕様の内容の把握を容易にすることである。

本処理の流れを、以下に示す。
本処理では、入力として受け取った、要求仕様情報オブジェクトのリスト内の各要求仕様情報オブジェクトに対して、以下の処理を繰り返す。

\begin{enumerate}
    \item 要求仕様テンプレートの部分文字列を格納する空のリストを用意する。
    \item 要求仕様情報オブジェクトからprecondition、trigger、system、responseの各プロパティの値を取得する。
    \item 取得した各プロパティの値に応じて、以下の処理を行う。
    \begin{itemize}
        \item preconditionプロパティの値が空文字列でない場合\\
        ``\{precondition\}場合''という形式の部分文字列をリストに追加する。
        \item triggerプロパティの値が空文字列でない場合\\
        ``\{trigger\}時''という形式の部分文字列をリストに追加する。
        \item systemプロパティとresponseプロパティの値が両方とも空文字列でない場合\\
        ``\{system\}は\{response\}べきである''という形式の部分文字列をリストに追加する。
    \end{itemize}
    \item リスト内の部分文字列を読点（、）で結合し、要求仕様テンプレートを生成する。
    \item 生成した要求仕様テンプレートを、要求仕様情報オブジェクトのdescriptionプロパティに代入する。    
\end{enumerate}

\subsubsection{対応付け可否判定処理}\label{subsubsec:req_traceability}
対応付け可否判定処理は、各要求仕様がテストケースと対応付け可能かどうかを判定する処理である。
本処理は、要求仕様テンプレート生成処理で生成した要求仕様情報オブジェクトのリストを入力とし、テストケースと対応付け可能かどうかを示すis\_traceableプロパティに値を代入した要求仕様情報オブジェクトのリストを出力とする。
本研究では、\cref{tb:traceability}で示す、要求仕様の対応付け要素 (「前提条件」、「トリガー」、「システム応答」)とテストケースの対応付け要素 (「事前条件」、「入力・操作」、「期待出力」)のそれぞれのテキスト間を比較し、要求仕様とテストケースの対応関係を抽出する。
そのため、要求仕様の対応付け要素のうち、いずれか$1$つでも対応付け要素の値が空文字列である要求仕様は、テストケースとの対応付けの対象外とする。

本処理の流れを、以下に示す。
本処理では、入力として受け取った、要求仕様情報オブジェクトのリスト内の各要求仕様情報オブジェクトに対して、以下の処理を繰り返す。

\begin{enumerate}
    \item 要求仕様情報オブジェクトのprecondition、trigger、response、3つのプロパティの値を取得する。
    \item 取得した3つのプロパティの値によって処理を分岐する。
    \begin{itemize}
        \item 3つのプロパティの値が全て空文字列でない場合\\
        テストケースとの対応付け可能な要求仕様と判定し、is\_traceableプロパティにtrueを代入する。
    \end{itemize}
    \begin{itemize}
        \item 3つのプロパティのうち、いずれか1つのプロパティの値が空文字列であった場合\\
        テストケースとの対応付け可能ではない要求仕様と判定し、is\_traceableプロパティにfalseを代入する。
    \end{itemize}
\end{enumerate}

\subsubsection{階層関係抽出処理}\label{subsubsec:req_hierarchy}
階層関係抽出処理は、要求仕様IDの命名規則 (\ref{sec:reqspec}節参照) に基づき、要求仕様間の親子関係の情報を抽出する処理である。
本処理は、対応付け可否判定処理で生成した要求仕様情報オブジェクトのリストを入力とし、要求仕様間の親子関係を示すparent\_idおよびchildren\_idsプロパティに値を代入した要求仕様情報オブジェクトのリストを、要求仕様情報リストとして出力する。
出力は、対応関係分析部(\ref{sec:correspondence-analysis}節で後述)および対応関係図生成部(\ref{sec:diagram-generation}節で後述)に渡す。
階層関係抽出の例を、表\ref{tb:hierarchy_example}に示す。

本処理の流れを、以下に示す。
\begin{enumerate}
    \item 入力として受け取った要求仕様情報オブジェクトのリストから、idプロパティの値をキー、リスト内の要求仕様情報オブジェクトへの参照を値とする辞書を生成する。
    \item 要求仕様情報オブジェクトのリストにある要求仕様情報オブジェクトの数だけ、以下の処理を繰り返す。
    \begin{enumerate}
        \item 要求仕様情報オブジェクトのリストより、要求仕様情報オブジェクトを1つ取得する。
        \item 取得した要求仕様情報オブジェクトのidプロパティの値をハイフン(\texttt{-})で分割し、分割結果の要素数を確認する。
        \item 分割結果の要素数に応じて、以下の処理を行う。
        \begin{itemize}
            \item 要素数が2個の場合 (例:``REQ-1'' の場合、分割結果[``REQ'' , ``1''])\\
            親要求仕様を持たない要求仕様情報オブジェクトのため、本要求仕様情報オブジェクトに対する以降の処理は行わず、
            リスト中の次の要求仕様情報オブジェクトに対して$2$.(a)からの処理を行う。
            \item 要素数が3個以上の場合 (例:``REQ-1-1-2'' の場合、分割結果[``REQ'' , ``1'' , ``1'', ``2''])\\
            親要求仕様を持つ子要求仕様オブジェクトのため、以下の処理を行う。
            \begin{enumerate}
                \item 分割結果の末尾要素を除いた部分をハイフン(\texttt{-})で結合し、親要求仕様のidプロパティの値を生成する。
                例えば、idプロパティの値が ``REQ-1-1-2'' の場合、分割結果[``REQ'' , ``1'' , ``1'', ``2'']のうち、末尾の ``2'' を除いた[ ``REQ'' , ``1'', ``1'']をハイフン(\texttt{-})結合し、親要求仕様のidプロパティの値 ``REQ-1-1'' を生成する。
                \item 生成した親要求仕様のidプロパティの値をキーとして、$1$.で生成した辞書から親要求仕様情報オブジェクトへの参照を取得する。
                \item 取得した参照を用いて、親要求仕様情報オブジェクトと$2$.(a)で取得した子要求仕様情報オブジェクトの間に、親子関係を双方向に記録する。
                具体的には、子要求仕様情報オブジェクトのparent\_idプロパティに親要求仕様情報オブジェクトのidプロパティの値を代入し、親要求仕様情報オブジェクトのchildren\_idsリストに子要求仕様情報オブジェクトのidプロパティの値を追加する。
            \end{enumerate}
        \end{itemize}
    \end{enumerate}
\end{enumerate}

\subsection{テストケース情報リスト生成処理}\label{sec:testcase-data-extraction}
テストケース情報リスト生成処理は、CSV形式で記述したテストケースを読み込み、処理部間のやり取りに用いる、テストケース情報リストを生成する処理である。
本処理は、CSV形式のテストケースを入力とし、テストケース情報リストを出力とする。本処理が入力として受け取るテストケースの例を、図\ref{fig:testcase_sample2}に示す。

\begin{figure}[tp]
    \centering
    \fbox{
        \includegraphics[width=0.96\textwidth]{images/testcase_sample2.png}
        }
        \caption{入力とするテストケースの例}
        \label{fig:testcase_sample2}
    \end{figure}

本処理の流れを、以下に示す。
\begin{enumerate}
    \item 空のリストを用意する。
    \item CSV形式のテストケースの数だけ、以下の処理を繰り返す。
    \begin{enumerate}
        \item CSV形式のテストケースを1つ取得する。
        \item 取得したCSVファイル名から拡張子(.csv)を除去し、テストスイート名として保持する。
        例えば、ファイル名が「ログインテスト.csv」の場合、「ログインテスト」をテストスイート名として保持する。
        \item CSV形式のテストケースを、DictReader関数(\ref{sec:Python}節を参照)を用いて読み込む\\
        CSVの1行目をヘッダー行 (テストケースID, テストケース名, 事前条件, 入力・操作, 期待出力)とし、2行目以降の各データ行を、ヘッダー行のカラム名をキーとした辞書形式で取得する。
        \item 各データ行について、以下の処理を繰り返す。
        \begin{enumerate}
            \item テストケース情報オブジェクトを生成し、辞書のキーに対応する値を、テストケース情報オブジェクトの各プロパティに代入する。
            \begin{itemize}
                \item idプロパティに``テストケースID''をキーとした値を代入する
                \item nameプロパティに``テストケース名''をキーとした値を代入する
                \item preconditionプロパティに``事前条件''をキーとした値を代入する
                \item operationプロパティに``入力・操作''をキーとした値を代入する
                \item expected\_outputプロパティに``期待出力''をキーとした値を代入する
                \item test\_suiteプロパティに$2$.(b)で保持しているテストスイート名を代入する
            \end{itemize}
            \item 生成したテストケース情報オブジェクトを、$1$.で用意したリストに追加する。
        \end{enumerate}
    \end{enumerate}
\end{enumerate}

% 対応関係分析部
\section{対応関係分析部}\label{sec:correspondence-analysis}
対応関係分析部は、入力解析部(\ref{sec:input-data-analysis}節参照)で生成した要求仕様情報リストとテストケース情報リストを分析し、要求仕様とテストケース間の対応関係を抽出する処理部である。
本処理部は、入力として要求仕様情報リストとテストケース情報リストを受け取り、対応関係情報リストを出力とする。
出力は、対応関係図生成部(\ref{sec:diagram-generation}節で後述)に渡す。

対応関係情報リストは、要求仕様とテストケース間の対応関係の情報を表したリストである。\\
対応関係情報リストは、以下に示す$5$つの情報を持つ。
\begin{itemize}
    \item 要求仕様ID: 要求仕様を一意に識別するID
    \item テストケースID: テストケースを一意に識別するID
    \item 合計スコア: $3$つの対応付け要素間の類似度の重み付け平均
    \item 各対応付け要素間の類似度: 前提条件と事前条件、トリガーと入力・操作、システム応答と期待出力の類似度
    \item 品質種別: 対応関係の十分性を示す\texttt{FULL} または \texttt{PARTIAL}
\end{itemize}

本処理部では、以下の$4$つの処理を行う。
\begin{itemize}
    \item 形態素解析処理(\cref{sec:morphological_analysis}節参照)
    \item 重要単語抽出処理(\cref{sec:imp_word}節参照)
    \item 類似度算出処理(\cref{subsec:similarity_calculation}節参照)
    \item 対応関係抽出処理(\cref{sec:traceability_extraction_processing}節参照)
\end{itemize}
以降、それぞれの処理について説明する。

\subsection{形態素解析処理}\label{sec:morphological_analysis}
形態素解析処理は、要求仕様情報リストとテストケース情報リストが含む対応付け要素の文字列を、MeCab (\cref{sec:Mecab}参照)を用いて形態素に分割し、基本形と品詞を取得する処理である。
本処理は、要求仕様情報リストとテストケース情報リストを入力とし、要求仕様形態素データリストおよびテストケース形態素データリストを出力とする。
出力は、重要単語抽出処理(\ref{sec:imp_word}節で後述)に渡す。

要求仕様形態素データリストは、各要求仕様の対応付け要素を形態素に分割し、その結果を格納したリストである。\\
要求仕様形態素データリストは、以下に示す$4$つの情報を持つ。
本研究では、形態素情報とは、各形態素の基本形と品詞からなる情報のことを表す。
\begin{itemize}
    \item 要求仕様ID: 要求仕様を一意に識別するID。
    \item 前提条件の形態素情報リスト: 前提条件の文字列を形態素に分割し、各形態素の基本形と品詞の対を保持したリスト
    \item トリガーの形態素情報リスト: トリガーの文字列を形態素に分割し、各形態素の基本形と品詞の対を保持したリスト
    \item システム応答の形態素情報リスト: システム応答の文字列を形態素に分割し、各形態素の基本形と品詞の対を保持したリスト
\end{itemize}

テストケース形態素データリストは、各テストケースの対応付け要素を形態素に分割し、その結果を格納したリストである。\\
テストケース形態素データリストは、以下に示す$4$つの情報を持つ。
\begin{itemize}
    \item テストケースID: テストケースを一意に識別するID
    \item 事前条件の形態素情報リスト: 事前条件の文字列を形態素に分割し、各形態素の基本形と品詞の対を保持したリスト
    \item 入力・操作の形態素情報リスト: 入力・操作の文字列を形態素に分割し、各形態素の基本形と品詞の対を保持したリスト
    \item 期待出力の形態素情報リスト: 期待出力の文字列を形態素に分割し、各形態素の基本形と品詞の対を保持したリスト
\end{itemize}

本処理の流れを、以下に示す。
\begin{enumerate}
    \item 入力解析部 (\cref{sec:input-data-analysis}参照) の出力である、要求仕様情報リストとテストケース情報を入力として読み込む。
    \item 要求仕様形態素データの生成\\
    要求仕様情報リストが持つ要求仕様情報オブジェクトの数だけ、以下の処理を繰り返す。
    \begin{enumerate}
        \item 要求仕様情報リストから、要求仕様オブジェクトを$1$つ取り出す。
        \item 取り出した要求仕様情報オブジェクトが対応付け可能要求仕様でない場合（is\_traceableプロパティの値がfalse）\\
            以降の処理は行わず、$2$.(a)の処理に戻る。
        \item 取り出した要求仕様情報オブジェクトから、要求仕様IDおよび$3$つの対応付け要素（「前提条件」、「トリガー」、「システム応答」）の文字列を抽出する。
        \item 抽出した$3$つの対応付け要素の文字列それぞれについて、以下の処理を実行する。
        \begin{enumerate}
            \item 空の形態素情報リストを用意する。
            \item 全角英数字を半角英数字に変換する前処理を行う。\\
            これは、「３」と「3」、「Ａ」と「A」のような表記揺れを統一し、類似度算出処理(\cref{subsec:similarity_calculation}節で後述) での精度を向上させる目的がある。
            \item MeCabを用いて、$2$.(d)ii. 後の文字列を形態素に分割し、基本形と品詞を抽出する。
            \item 抽出した基本形と品詞の対を形態素情報として、$2$.(d)i.で用意した形態素情報リストに追加する。
        \end{enumerate}
        \item 要求仕様IDと$3$つの対応付け要素の形態素情報リストから、要求仕様形態素データを生成する。
    \end{enumerate}
    \item テストケース形態素データの生成\\
    テストケース情報リストが持つテストケース情報オブジェクトの数だけ、以下の処理を繰り返す。
    \begin{enumerate}
        \item テストケース情報リストから、テストケース情報オブジェクトを$1$つ取り出す。
        \item 取り出したテストケース情報オブジェクトから、テストケースIDおよび$3$つの対応付け要素（「事前条件」、「入力・操作」、「期待出力」）の文字列を抽出する。
        \item 抽出した$3$つの対応付け要素の文字列それぞれについて、$2$.(d)と同様の処理を実行する。
        \item テストケースIDと$3$つの対応付け要素の形態素情報リストから、テストケース形態素データを生成する。
    \end{enumerate}
    \item 要求仕様形態素データとテストケース形態素データのリスト化\\
    $2$.で生成した全要求仕様形態素データ と $3$.で生成した全テストケース形態素データをそれぞれリスト化し、要求仕様形態素データリストおよびテストケース形態素データリストを生成する。
\end{enumerate}

\subsection{重要単語抽出処理}\label{sec:imp_word}
重要単語抽出処理は、形態素解析処理(\cref{sec:morphological_analysis}節参照)で生成した要求仕様形態素データリストおよびテストケース形態素データリストから、重要単語を抽出する処理である。
本処理は、要求仕様形態素データリストとテストケース形態素データリストを入力とし、要求仕様重要単語データリストおよびテストケース重要単語データリストを出力とする。
出力は、類似度算出処理(\ref{subsec:similarity_calculation}節で後述)に渡す。

本研究では、重要単語として名詞、動詞、複合名詞を抽出する。
名詞は要求仕様やテストケースにおいて、対象物や概念を表し、動詞はシステムの動作や振る舞いを表すため、対応付けにおいて重要な意味を持つ。
また、複合名詞は、2個以上の連続する名詞から成り、先頭に接頭辞を伴うことがある単語と定義し、単独の名詞よりも要求仕様やテストケースの内容を具体的に表すことができるため抽出する。

要求仕様重要単語データリストは、各要求仕様の対応付け要素から抽出した重要単語を格納するリストである。\\
要求仕様重要単語データリストは、以下に示す$4$つの情報を持つ。
\begin{itemize}
    \item 要求仕様ID: 要求仕様を一意に識別するID。
    \item 前提条件の重要単語リスト: 前提条件の形態素情報リストから抽出した名詞、動詞、複合名詞からなるリスト
    \item トリガーの重要単語リスト: トリガーの形態素情報リストから抽出した名詞、動詞、複合名詞からなるリスト
    \item システム応答の重要単語リスト: システム応答の形態素情報リストから抽出した名詞、動詞、複合名詞からなるリスト
\end{itemize}

テストケース重要単語データリストは、各テストケースの対応付け要素から抽出した重要単語を格納するリストである。\\
テストケース重要単語データリストは、以下に示す$4$つの情報を持つ。
\begin{itemize}
    \item テストケースID: テストケースを一意に識別するID。
    \item 事前条件の重要単語リスト: 事前条件の形態素情報リストから抽出した名詞、動詞、複合名詞からなるリスト
    \item 入力・操作の重要単語リスト: 入力・操作の形態素情報リストから抽出した名詞、動詞、複合名詞からなるリスト
    \item 期待出力の重要単語リスト: 期待出力の形態素情報リストから抽出した名詞、動詞、複合名詞からなるリスト
\end{itemize}

本処理の流れを、以下に示す。
\begin{enumerate}
    \item 形態素解析処理 (\cref{sec:morphological_analysis}節参照) の出力である、要求仕様形態素データリストとテストケース形態素データリストを入力として読み込む。
    \item 要求仕様重要単語データの生成\\
    要求仕様形態素データリストが持つ要求仕様形態素データの数だけ、以下の処理を繰り返す。
    \begin{enumerate}
        \item 要求仕様形態素データリストから、要求仕様形態素データを$1$つ取り出す。
        \item 取り出した要求仕様形態素データから、要求仕様IDおよび$3$つの対応付け要素の形態素情報リストを抽出する。
        \item 抽出した$3$つの対応付け要素の形態素情報リストそれぞれについて、以下の処理を実行する。
        \begin{enumerate}
            \item 空の名詞リスト、動詞リスト、複合名詞候補リスト、複合名詞リストを用意する。
            \item 形態素情報リストの走査\\
            形態素情報リストを先頭から順に走査し、各形態素の品詞に応じて以下の処理を行う。
            \begin{enumerate}
                \item 形態素の品詞が名詞の場合
                \begin{itemize}
                    \item 形態素情報リスト内の次の形態素が名詞以外の場合\\
                    本名詞を$2$.(c)i.で用意した名詞リストに追加する。
                    \item 形態素情報リスト内の次の形態素が名詞の場合\\
                    名詞以外の形態素が現れるまで走査し、連続する名詞を結合して$2$.(c)i.で用意した複合名詞候補リストに追加する。
                \end{itemize}
                \item 形態素の品詞が接頭辞の場合
                \begin{itemize}
                    \item 形態素情報リスト内の次の形態素が名詞以外の場合\\
                    形態素情報リスト内の次の形態素を走査する。
                    \item 形態素情報リスト内の次の形態素が名詞の場合\\
                    名詞以外の形態素が現れるまで走査し、接頭辞と連続する名詞を結合して$2$.(c)i.で用意した複合名詞候補リストに追加する。
                \end{itemize}
                \item 形態素の品詞が動詞の場合\\
                $2$.(c)i.で用意した動詞リストに追加する。
            \end{enumerate}
            \item 複合名詞の妥当性判定\label{enum:妥当性判定}\\
            複合名詞候補リスト内の各単語に対して、以下の条件を全て満たす場合、妥当な複合名詞と判定し、$2$.(c)i.で用意した複合名詞リストに追加する。
            \begin{itemize}
                \item 文字数が$20$文字以下である\\
                $20$文字を超える複合名詞は、異常に長い文字列として除外する。
                \item 同じ文字の繰り返しでない\\
                例えば、「あああ」のように同一文字の繰り返しは、形態素解析の誤りである可能性が高いため除外する。
            \end{itemize}

            \item 重要単語リストの結合\\
            名詞リスト、動詞リスト、複合名詞リストを結合し、対応付け要素の重要単語リストとして保持する。
        \end{enumerate}
        \item 要求仕様IDと$3$つの対応付け要素の重要単語リストから、要求仕様重要単語データを生成する。
    \end{enumerate}

    \item テストケース重要単語データの生成\\
    テストケース形態素データリストが持つテストケース形態素データの数だけ、以下の処理を繰り返す。
    \begin{enumerate}
        \item テストケース形態素データリストから、テストケース形態素データを$1$つ取り出す。
        \item 取り出したテストケース形態素データから、テストケースIDおよび$3$つの対応付け要素の形態素情報リストを抽出する
        \item $2$.(c)と同様の処理を実行する。
        \item テストケースIDと$3$つの対応付け要素の重要単語リストから、テストケース重要単語データを生成する。
    \end{enumerate}
    \item 要求仕様重要単語データとテストケース重要単語データのリスト化\\
    $2$.で生成した全要求仕様重要単語データ と $3$.で生成した全テストケース重要単語データをそれぞれリスト化し、要求仕様重要単語データリストとテストケース重要単語データリストを生成する。
\end{enumerate}

\subsection{類似度算出処理}\label{subsec:similarity_calculation}
類似度算出処理は、重要単語抽出処理 (\cref{sec:imp_word}節参照) で生成した要求仕様重要単語データリストおよびテストケース重要単語データリストを用いて、全ての要求仕様とテストケースの組み合わせで類似度を算出する処理である。
本処理は、要求仕様重要単語データリストおよびテストケース重要単語データリストを入力とし、対応付け情報リストを出力とする。
出力は、対応関係抽出処理(\ref{sec:traceability_extraction_processing}節で後述)に渡す。

対応付け情報リストは、要求仕様とテストケース間の類似度の情報を表したリストである。\\
対応付け情報リストは、以下に示す$4$つの情報を持つ。
\begin{itemize}
    \item 要求仕様ID: 要求仕様を一意に識別するID
    \item テストケースID: テストケースを一意に識別するID
    \item 合計スコア: $3$つの対応付け要素間の類似度の重み付け平均
    \item 各対応付け要素間の類似度: 前提条件と事前条件、トリガーと入力・操作、システム応答と期待出力の類似度
\end{itemize}

本処理では、$2$つのテキスト間の類似度を測る指標としてJaccard係数(\ref{sec:Jaccard}節参照)を使用する。

本処理の流れを、以下に示す。
\begin{enumerate}
    \item 重要単語抽出処理 (\cref{sec:imp_word}節参照) の出力である、要求仕様重要単語データリストとテストケース重要単語データリストを入力として読み込む。
    \item 空のリストを用意する。
    \item 要求仕様重要単語データリスト内の要求仕様重要単語データとテストケース重要単語データリスト内のテストケース重要単語データの全ての組み合わせにおいて、以下の処理を繰り返す。
    \begin{enumerate}
        \item 要求仕様重要単語データから、要求仕様IDと$3$つの対応付け要素の重要単語リストを抽出する。同様に、テストケース重要単語データから、テストケースIDと$3$つの対応付け要素の重要単語リストを抽出する。
        \item $3$.(a)で抽出した重要単語リストから、以下の$3$つの対応付け要素間について、Jaccard係数を用いて類似度を算出する。
        \begin{itemize}
            \item 「前提条件」と「事前条件」
            \item 「トリガー」と「入力・操作」
            \item 「システム応答」と「期待出力」
        \end{itemize}
        \item $3$.(b)で算出した $3$つの対応付け要素間の類似度に対して、初期設定(\cref{sec:config}参照)で設定した重みを掛けて合算し、合計スコアを算出する。合計スコアの算出式を\cref{eq:total_score}に示す。

        \begin{equation}
            S_{\text{total}} = w_1 \cdot S_{\text{pre}} + w_2 \cdot S_{\text{trig}} + w_3 \cdot S_{\text{resp}}\label{eq:total_score}
        \end{equation}

        ここで、$S_{\text{pre}}$は「前提条件」と「事前条件」の類似度、$S_{\text{trig}}$は「トリガー」と「入力・操作」の類似度、$S_{\text{resp}}$は「システム応答」と「期待出力」の類似度である。また、$w_1, w_2, w_3$はそれぞれの重みを表す。

        \item $3$.(a)で抽出した要求仕様IDとテストケースID、$3$.(b)で算出した各対応付け要素間の類似度および$3$.(c)で算出した合計スコアを対応付け情報として、$2$.で用意したリストに追加する。
    \end{enumerate}
\end{enumerate}

\subsection{対応関係抽出処理}\label{sec:traceability_extraction_processing}
対応関係抽出処理は、類似度算出処理(\cref{subsec:similarity_calculation}節参照)で生成した対応付け情報リストから、要求仕様とテストケースの対応関係を抽出する処理である。
本処理は、対応付け情報リストを入力とし、対応関係情報リストを出力とする。
出力は、対応関係図生成部(\cref{sec:diagram-generation}節参照)に渡す。

本処理の流れを、以下に示す。
\begin{enumerate}
    \item 類似度算出処理 (\cref{subsec:similarity_calculation}節参照) の出力である、対応付け情報リストを入力として読み込む。
    \item 空の対応関係候補リストを用意する。
    \item 対応付け情報リスト内の対応付け情報の数だけ、以下の処理を繰り返す。
    \begin{enumerate}
        \item 対応付け情報リストから、対応付け情報を1つ取り出す。
        \item 取り出した対応付け情報から、合計スコアを取得する。
        \begin{itemize}
            \item 合計スコアが初期設定(\cref{sec:config}参照)で設定した閾値未満の場合\\
            $3$.(a)の処理に戻り、次の対応付け情報を処理する。
            \item 合計スコアが初期設定(\cref{sec:config}参照)で設定した閾値以上の場合\\
            $2$.で用意した対応関係候補リストに追加する。
        \end{itemize}
    \end{enumerate}
    \item 対応関係候補リストを、合計スコアの降順にソートする。
    \item 空の対応関係情報リストを用意する。
    \item 対応関係候補リスト内の対応関係候補の数だけ、以下の処理を繰り返す。
    \begin{enumerate}
        \item 対応関係候補リストから、対応関係候補を1つ取り出す。
        \item 取り出した対応関係候補から、要求仕様IDおよびテストケースIDを取得する。
        \begin{itemize}
            \item 対応関係候補の要求仕様IDまたはテストケースIDが、すでに対応関係情報リストに存在する場合\\
            $6$.(a)の処理に戻り、次の対応関係候補を処理する。
            \item 対応関係候補の要求仕様IDおよびテストケースIDが、対応関係情報リストに存在しない場合\\
            取り出した対応関係候補を、$5$.で用意した対応関係情報リストに追加する。
        \end{itemize}
    \end{enumerate}
    \item 対応関係情報リスト内の対応関係情報の数だけ、以下の処理を繰り返す。
    \begin{enumerate}
        \item 対応関係情報リストから、対応関係情報を1つ取り出す。
        \item 取り出した対応関係情報から、$3$つの対応付け要素間の類似度（「前提条件」と「事前条件」、「トリガー」と「入力・操作」、「システム応答」と「期待出力」）を取得する。
        \item 取得した各類似度が閾値以上であるかを確認し、閾値以上である類似度の数を数える。
        \begin{itemize}
            \item 閾値以上である類似度の数が$3$つの場合\\
            取り出した対応関係の品質種別に\texttt{FULL}を設定する。
            \item 閾値以上である類似度の数が$1$つまたは$2$つの場合\\
            取り出した対応関係の品質種別に\texttt{PARTIAL}を設定する。
        \end{itemize}
    \end{enumerate}
    \item 対応関係情報リストを、対応関係図生成部(\ref{sec:diagram-generation}節参照)に渡す。
\end{enumerate}

% 対応関係図生成部
\section{対応関係図生成部}\label{sec:diagram-generation}
対応関係図生成部は、要求仕様とテストケースの対応関係からテストケースの抜けや不備、過剰箇所を可視化した図を生成する処理部である。
本処理部は、入力として要求仕様情報リスト、テストケース情報リスト、および対応関係情報リストを受け取り、対応関係図をブラウザ上に表示する。

本処理部では、以下の$2$つの処理を行う。
\begin{itemize}
    \item PlantUMLコード生成処理(\cref{subsec:puml-generation}節参照)
    \item 対応関係図生成処理(\cref{subsec:diagram-generation-process}節参照)
\end{itemize}
以降、それぞれの処理について説明する。

\subsection{PlantUMLコード生成処理}\label{subsec:puml-generation}
PlantUMLコード生成処理は、対応関係図を生成するためのPlantUMLコードを生成する処理である。
本処理は、要求仕様情報リスト、テストケース情報リスト、および対応関係情報リストを入力とし、PlantUMLコードを出力とする。
出力は、対応関係図生成処理(\ref{subsec:diagram-generation-process}節で後述)に渡す。
本処理では、空の文字列の変数であるpuml\_codeを用意し、対応関係図を生成するためのPlantUMLコードを変数puml\_codeに追加していく。
表\ref{tab:puml-settings}に図の設定、表\ref{tab:color-mapping}に品質種別と色の対応を示す。

本処理の流れを、以下に示す。
\begin{enumerate}
    \item 入力解析部の (\cref{sec:input-data-analysis}参照) の出力である、要求仕様情報リストとテストケース情報リスト、および対応関係分析部 (\cref{sec:correspondence-analysis}参照) の出力である、対応関係情報リストを入力として読み込む。
    \item PlantUMLコード開始タグおよび表\ref{tab:puml-settings}に示す図の設定を、変数puml\_codeに追加する。
    \item 要求仕様エリアの生成\\
    要求仕様エリアの開始タグを、変数puml\_codeに追加し、要求仕様情報リスト内の各要求仕様情報オブジェクトについて、以下の処理を繰り返す。
    \begin{enumerate}
        \item 要求仕様情報オブジェクトのis\_traceableプロパティの値を取得する。
        \item 取得した値によって、各要求仕様の矩形要素に色を設定する。
        \begin{itemize}
            \item テストケースと対応付け可能ではない要求仕様 (is\_traceableプロパティの値がfalse) の場合\\
            色を設定せず、要求仕様情報リスト内の次の要求仕様情報オブジェクトの処理に移る。
            \item テストケースと対応付け可能な要求仕様 (is\_traceableプロパティの値がtrue) の場合\\
            対応関係情報リストから、要求仕様情報オブジェクトのidプロパティの値と一致する要求仕様IDを持つ対応関係情報を探索する。
            \begin{itemize}
                \item 該当する対応関係情報が存在しない場合\\
                表\ref{tab:color-mapping}に示す「WEAK」の色を設定する。
                \item 該当する対応関係情報が存在する場合\\
                対応関係情報の品質種別に基づき、表\ref{tab:color-mapping}に示す色を設定する。
            \end{itemize}
        \end{itemize}
        \item 要求仕様情報オブジェクトのid、name、descriptionプロパティの値と、$3$.(b)で設定した色を用いて、各要求仕様の矩形要素を表すPlantUMLコードを生成し、変数puml\_codeに追加する。
    \end{enumerate}
    全ての要求仕様情報オブジェクトの処理が終了したら、要求仕様情報オブジェクトのparent\_idおよびchildren\_idsプロパティの値を用いて、
    要求仕様の親子関係の線を表すPlantUMLコードを生成し、要求仕様エリアの終了タグを変数puml\_codeに追加する。

    \item テストケースエリアの生成\\
    テストケースエリアの開始タグを、変数puml\_codeに追加し、テストケース情報リストをtest\_suiteプロパティの値でグループ化し、各グループについて以下の処理を繰り返す。
    \begin{enumerate}
        \item test\_suiteプロパティの値をテストスイート名として、テストスイートエリアの開始タグを変数puml\_codeに追加する。
        \item グループ内の各テストケース情報オブジェクトについて、以下の処理を繰り返す。
        \begin{enumerate}
            \item 対応関係情報リストから、テストケース情報オブジェクトのidプロパティの値と一致するテストケースIDを持つ対応関係情報を探索し、各テストケースの矩形要素に色を設定する。
            \begin{itemize}
                \item 該当する対応関係情報が存在しない場合\\
                表\ref{tab:color-mapping}に示す「WEAK」の色を設定する。
                \item 該当する対応関係情報が存在する場合\\
                対応関係情報の品質種別に基づき、表\ref{tab:color-mapping}に示す色を設定する。
            \end{itemize}
            \item テストケース情報オブジェクトのid、name、precondition、operation、expected\_outputプロパティの値と、$4$.(b)i.で設定した色を用いて、各テストケースの矩形要素を表すPlantUMLコードを生成し、変数puml\_codeに追加する。
        \end{enumerate}
        \item テストスイートエリアの終了タグを変数puml\_codeに追加する。
    \end{enumerate}
    \item 全てのグループの処理が終了したら、テストケースエリアの終了タグを変数puml\_codeに追加する。
    \item 要求仕様エリアとテストケースエリアを生成後、対応関係情報リストに基づき、対応関係がある要求仕様の矩形要素とテストケースの矩形要素を、合計スコアのラベルを付与した点線で結ぶPlantUMLコードを生成し、変数puml\_codeに追加する。
    \item PlantUMLコード終了タグを、変数puml\_codeに追加する。
    \item 変数puml\_codeをPlantUMLコードとして、対応関係図生成処理 (\cref{subsec:diagram-generation-process}参照) に渡す。
\end{enumerate}

\subsection{対応関係図生成処理}\label{subsec:diagram-generation-process}
対応関係図生成処理は、PlantUMLコード生成処理(\ref{subsec:puml-generation}節参照)で生成したPlantUMLコードを、SVG画像に変換し、ブラウザ上に表示する処理である。
本処理は、PlantUMLコードを入力とし、SVG画像をブラウザ上で表示する。

本処理の流れを、以下に示す。
\begin{enumerate}
    \item 対応関係図生成部の (\cref{sec:diagram-generation}参照) の出力である、PlantUMLコードを入力として読み込む。
    \item PlantUMLコードを.pumlファイルとして保存する。
    \item PlantUMLライブラリを用いて、.pumlファイルからSVG画像を生成する。
    \item 生成したSVG画像を、http.serverモジュール(\cref{sec:Python}参照)を用いたローカルサーバーを経由して、ブラウザ上に表示する。
\end{enumerate}
