試作した\tool{}がTCVダイアグラムを正しく出力できることを確認するため、
以下のテストケースの過不足箇所(\ref{sec:words}節参照)を意図的に含めた。

\begin{itemize}                                                                                                                     
    \item テストケースの抜け \\                                                                                                     
    要求仕様REQ-1-2-3と対応関係があるテストケースが存在しない。                                                                     
    \item テストケースの不備 \\                                                                                                     
    テストケースTC-3の期待出力を表す文章『「閏年ではありません」と出力される』と、                                                            
    要求仕様REQ-1-1-3のシステム応答を表す文章『「閏年です」と出力する』とで出力内容が異なっており、
    要求仕様に対して、テストケースの内容が不十分である。                                                                                                        
    \item テストケースの過剰 
    \begin{itemize}
        \item テストケースTC-5と対応関係がある要求仕様が存在しない。
        \item テストケースTC-9と対応関係がある要求仕様が存在しない。
    \end{itemize}
\end{itemize}

以降、図\ref{fig:tcv_diagram_application_example}を用いて、\tool{}が正しくTCVダイアグラムを出力できたことを確認する。                                      

具体的には、TCVダイアグラムが以下の9つの項目を満たすことを確認する。

\begin{itemize}
    \item 要求仕様の矩形要素を正しく表示していること\\
    図\ref{fig:tcv_diagram_application_example}において、要求仕様REQ-1の矩形要素に着目する。
    要求仕様REQ-1の矩形要素は、要求仕様ID「REQ-1」、要求仕様名「閏年判定機能」、
    および要求仕様文(\ref{sec:EARS}節参照)を正しく表示しており、
    図\ref{fig:reqspec_application_example}の要求仕様書に記述した内容と一致していることが確認できる。
    また、図\ref{fig:tcv_diagram_application_example}における、他の要求仕様の矩形要素についても同様に、正しく表示していることが確認できる。

    \item テストケースの矩形要素を正しく表示していること\\
    図\ref{fig:tcv_diagram_application_example}において、テストケースTC-1の矩形要素に着目する。
    テストケースTC-1の矩形要素は、テストケースID「TC-1」、テストケース名「400で割り切れる年の判定テスト」、
    事前条件、操作、および期待出力の内容を正しく表示しており、
    図\ref{fig:testsuite_judge_leap_year}のテストスイートに記述した内容と一致していることが確認できる。
    また、図\ref{fig:tcv_diagram_application_example}における、他のテストケースの矩形要素についても同様に、正しく表示していることが確認できる。

    \item テストケースをテストスイートごとにまとめて配置していること\\
    図\ref{fig:tcv_diagram_application_example}において、テストケースエリアに着目する。
    図\ref{fig:testsuite_judge_leap_year}のテストスイート「閏年判定テスト」に属するテストケースは、
    同一のテストスイートエリア内にまとめて配置している。
    同様に、図\ref{fig:testsuite_input_format_validation}のテストスイート「入力形式検証テスト」に属するテストケースも、
    同一のテストスイートエリア内にまとめて配置している。
    したがって、テストケースを正しくテストスイートごとにまとめて配置していることが確認できる。

    \item 要求仕様間の親子関係を表現していること\\                                                                                             
    図\ref{fig:tcv_diagram_application_example}において、要求仕様REQ-1の矩形要素と要求仕様REQ-1-1の矩形要素の2つに着目する。
    子要求仕様REQ-1-1の矩形要素から親要求仕様REQ-1の矩形要素へ向かう実線矢印は、                                                       
    要求仕様間の親子関係を正しく表現していることが確認できる。
    また、図\ref{fig:tcv_diagram_application_example}における、他の要求仕様間の親子関係についても同様に、正しく表現していることが確認できる。

    \item 対応付け不可能な要求仕様の矩形要素を表示していること\\                                                                                     
    図\ref{fig:tcv_diagram_application_example}において、要求仕様REQ-1、REQ-1-1、REQ-1-2の矩形要素に着目する。                                                
    これらの要求仕様は、\ref{sec:words}節で述べた対応付け不可能な要求仕様である。                                                  
    そのため、これらの要求仕様の矩形要素は、品質種別に対応する白色(UNTRACEABLE)の背景色で表示しており、                                                                   
    対応付け不可能な要求仕様の矩形要素を正しく表示していることが確認できる。

    \item テストケースの充足箇所を強調していること\\                                                                             
    図\ref{fig:tcv_diagram_application_example}において、要求仕様REQ-1-1-1の矩形要素とテストケースTC-1の矩形要素の2つに着目する。
    これらの矩形要素は、品質種別に対応する緑色(FULL)の背景色で表示しており、
    合計スコア0.90をラベルとして付与した破線で接続している。
    この合計スコアは、図\ref{fig:setting_application_example}で設定した類似度の閾値 (similarity\_threshold) 0.7以上である。
    したがって、テストケースの充足箇所を正しく強調していることが確認できる。
    また、図\ref{fig:tcv_diagram_application_example}における、他のテストケースの充足箇所についても同様に、正しく表示していることが確認できる。

    \item テストケースの抜け箇所を強調していること\\
    図\ref{fig:tcv_diagram_application_example}において、要求仕様REQ-1-2-3の矩形要素に着目する。               
    図\ref{fig:testsuite_judge_leap_year}および図\ref{fig:testsuite_input_format_validation}のテストスイートには、                    
    要求仕様REQ-1-2-3と対応関係があるテストケースが存在しない。                                   
    そのため、要求仕様REQ-1-2-3の矩形要素は、                                                     
    品質種別に対応する赤色(NONE)の背景色で表示しており、                                          
    テストケースの抜け箇所を正しく強調していることが確認できる。

    \item テストケースの不備箇所を強調していること\\
    図\ref{fig:tcv_diagram_application_example}において、
    要求仕様REQ-1-1-3の矩形要素とテストケースTC-3の矩形要素の2つに着目する。
    これらの矩形要素は、合計スコア0.84をラベルとして付与した破線で接続しているため、
    要求仕様REQ-1-1-3とテストケースTC-3には、対応関係がある。                                                         
    しかし、要求仕様REQ-1-1-3のシステム応答を表す文章『「閏年です」と出力する』と、                       
    テストケースTC-3の期待出力を表す文章『「閏年ではありません」と出力される』とで出力内容が異なっており、
    一部の対応付け要素間(システム応答と期待出力)の類似度が、図\ref{fig:setting_application_example}で設定した類似度の閾値 (similarity\_threshold) 0.7未満である。                                                                                          
    そのため、これらの矩形要素は、品質種別に対応する黄色(PARTIAL)の背景色で表示しており、         
    テストケースの不備箇所を正しく強調していることが確認できる。

    \item テストケースの過剰箇所を強調していること\\
    図\ref{fig:tcv_diagram_application_example}において、テストケースTC-5およびTC-9の矩形要素に着目する。                                          
    図\ref{fig:reqspec_application_example}の要求仕様書には、これらのテストケースと対応関係がある要求仕様が存在しない。                                   
    そのため、これらの矩形要素は、品質種別に対応する赤色(NONE)の背景色で表示しており、                                                
    テストケースの過剰箇所を正しく強調していることが確認できる。
    なお、\ref{subsubsec:tc_excess}節で述べたように、                                                                           
    ユーザーは、テストケースの過剰箇所に対して、不要であれば、テストケースの削除、                                                                    
    または、対応する要求仕様の追加を検討できる。                                                                                      
    テストケースTC-5「閏年の2月日数表示テスト」は、
    図\ref{fig:reqspec_application_example}の要求仕様書に記述していない、2月の日数表示機能を対象としたテストケースであり、
    閏年判定システムの機能範囲外であるため、不要なテストケースとして削除を検討できる。
    一方、テストケースTC-9「全角数字入力テスト」は、
    西暦年に全角数字を入力した際の、エラー出力をテストするテストケースであり、
    閏年判定システムが持つべき入力値検証機能に該当すると考えられるため、
    対応する要求仕様の追加を検討できる。
\end{itemize}

以上の9つの項目から、\tool{}は、入力に対して正しくTCVダイアグラムを出力することを確認できた。
