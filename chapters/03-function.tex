\chapter{\tool{}の機能}\label{cha:Function}

本章では、本研究で試作するツール\tool{} (VIsualization of Testcase Tool) の機能について説明する。

\tool は、\ref{subsec:reqspec}節で述べた要求仕様書、および、\ref{subsec:testsuite}節で述べたテストスイートを入力とし、
TCVダイアグラム(\cref{sec:testcase_visualization_diagram}で後述)を出力する。

以降、TCVダイアグラムの詳細を\ref{sec:testcase_visualization_diagram}節で、
\tool を使用する際に必要な初期設定を\ref{sec:config}節で、
\tool 使用時の流れを\ref{sec:flow_using_tool}節で、それぞれ説明する。

% TCVダイアグラム
\section{TCVダイアグラム}\label{sec:testcase_visualization_diagram}
TCVダイアグラム (Test-Case Visualization Diagram) とは、本研究で提案する、テストケースの可視化を目的としたダイアグラムである。

具体的には、TCVダイアグラムは、以下を可視化する。
\begin{itemize}
    \item テストケースの充足\\
    ある要求仕様を適正にテストするテストケースが存在する状態
    \item テストケースの過不足\\
    以下のテストケースの抜け、テストケースの不備、テストケースの過剰の3つのテストケースの状態の総称
    \begin{itemize}
        \item テストケースの抜け\\
        ある要求仕様をテストするテストケースが存在しない状態
        \item テストケースの不備\\
        ある要求仕様をテストするテストケースは存在するが、内容が要求仕様に対して不十分な状態
        \item テストケースの過剰\\
        テストケースは存在するが、テストする要求仕様が存在しない状態
    \end{itemize}
\end{itemize}

以降、TCVダイアグラムの構成を \cref{subsec:tcv_structure} 節で、TCVダイアグラムによるテストケースの可視化について\cref{subsec:tcv_visualization}節で、それぞれ説明する。

\subsubsection{要求仕様エリア}\label{subsec:requirements_area}
要求仕様エリアは、入力の要求仕様書が含む各要求仕様の矩形要素を表示する領域である。
図\ref{fig:tcv_diagram_with_area}において、①の領域が該当する。
要求仕様エリアでは、要求仕様IDの命名規則(\ref{subsec:reqspec}節参照)に基づき、子要求仕様の矩形要素から親要求仕様の矩形要素へ向かう実線矢印を描画することで、要求仕様の親子関係を視覚的に表現する。
例えば、図\ref{fig:tcv_diagram_with_area}では、REQ-1-1からREQ-1へ向かう矢印により、REQ-1-1がREQ-1の子要求仕様であることを表現している。

\subsubsection{テストケースエリア}\label{subsec:testcases_area}
テストケースエリアは、入力のテストスイートが含む各テストケースの矩形要素を表示する領域である。
図\ref{fig:tcv_diagram_with_area}において、②の領域が該当する。
テストケースエリアでは、要求仕様エリアとは異なり、テストケース間の階層関係は持たない。
例えば、図\ref{fig:tcv_diagram_with_area}では、入力のテストスイートが含む6個のテストケースの矩形要素を、階層関係を持たずに並列に配置している。

\subsubsection{テストスイートエリア}\label{subsec:testsuite_area}
テストスイートエリアは、テストケースエリア内において、同一のテストスイートに属するテストケースをグループ化して表示する領域である。
図\ref{fig:tcv_diagram_with_area}において、③の領域が該当する。
テストスイートエリアでは、テストスイートのCSVファイル名から抽出したテストスイート名を、各テストスイートエリアの上部に中央揃えで表示し、
同一のテストスイートに属するテストケースの矩形要素は、同じテストスイートエリア内にまとめて配置する。
例えば、図\ref{fig:tcv_diagram_with_area}では、「入力形式検証テスト」と「三角形種類判定テスト」の2つのテストスイートエリアがあり、
それぞれのテストスイートに属するテストケースをグループ化して表示している。

\subsection{TCVダイアグラムによるテストケースの可視化}\label{subsec:tcv_visualization}
TCVダイアグラムは、要求仕様とテストケース間の対応関係の状態を「品質種別」として定義し、品質種別に応じた背景色を各矩形要素に設定する。
品質種別の定義と対応する背景色を、表\ref{tab:quality_type}に示す。

\begin{table}[tp]
    \caption{品質種別の定義と対応する背景色}\label{tab:quality_type}
    \centering
    \begin{tabular}{l|l|l}
        \multicolumn{1}{c|}{品質種別} & \multicolumn{1}{c|}{定義} & \multicolumn{1}{c}{色} \\
        \hline
        \hline
        \texttt{FULL} & 全ての対応付け要素間の類似度が閾値以上である状態 & 緑 \\
        \hline
        \texttt{PARTIAL} & 一部の対応付け要素間の類似度が閾値未満である状態 & 黄 \\
        \hline
        \texttt{NONE} & 対応付け可能な要求仕様とテストケース間に対応関係が存在しない状態 & 赤 \\
        \hline
        \texttt{UNTRACEABLE} & テストケースと対応付け不可能な要求仕様 & 白 \\
        \hline
    \end{tabular}
\end{table}

以降、TCVダイアグラムによって可視化する以下について、説明する。

\begin{itemize}
    \item テストケースの充足
    \item テストケースの過不足
    \begin{itemize}
        \item テストケースの抜け
        \item テストケースの不備
        \item テストケースの過剰
    \end{itemize}
\end{itemize}

\subsubsection{テストケースの充足}\label{subsubsec:tracability_link}
TCVダイアグラムは、対応関係がある要求仕様の矩形要素およびテストケースの矩形要素の2つを、
品質種別に対応する緑色(FULL)で表示することで、テストケースの充足箇所を強調する。
図\ref{fig:tracability_link}は、図\ref{fig:tcv_diagram_with_area}における要求仕様REQ-1-1-1とテストケースTC-1を示している。
対応関係がある要求仕様の矩形要素とテストケースの矩形要素の2つは、破線で接続する。
この破線には、類似度算出処理(\ref{subsec:similarity_calculation}節で後述)で算出した合計スコアをラベルとして破線の下に付与する。
ユーザーは、緑色で表示した要求仕様とテストケースを確認することで、テストケースの充足箇所を把握できる。

\end{figure}

\subsubsection{テストケースの抜け}\label{subsubsec:missing_testcase}
TCVダイアグラムは、対応するテストケースが存在しない要求仕様の矩形要素を、品質種別に対応する赤色(NONE)で表示することで、テストケースの抜け箇所を強調する。
図\ref{fig:missing_testcase}は、図\ref{fig:tcv_diagram_with_area}における要求仕様REQ-1-1-2を示しており、この要求仕様を検証するテストケースが存在しないことを表している。
ユーザーは、赤色で表示した要求仕様を確認することで、テストケースの抜け箇所を把握し、この要求仕様に対応した新たなテストケースの作成を検討できる。

\subsubsection{テストケースの不備}\label{subsubsec:insufficient_testcase}
TCVダイアグラムは、対応関係は存在するが、一部の対応付け要素間の類似度が閾値未満である場合、要求仕様の矩形要素およびテストケースの矩形要素の2つを、品質種別に対応する黄色(PARTIAL)で表示することで、テストケースの不備箇所を強調する。
図\ref{fig:insufficient_testcase}は、図\ref{fig:tcv_diagram_with_area}における要求仕様REQ-1-1-3とテストケースTC-3を示している。

ユーザーは、黄色で表示した要求仕様とテストケースを確認することで、テストケースの不備箇所を把握し、テストケースの内容を見直すことができる。

\section{初期設定}\label{sec:config}

\tool を使用するために、プロジェクトの情報や、要求仕様とテストケースの対応関係を抽出する際に用いるパラメータを、\tool{}の設定ファイルvitt.yamlに事前に記述する必要がある。
設定ファイルvitt.yamlは、プロジェクト設定(project)と処理設定(processing)の2つの項目から構成する。

設定ファイルvitt.yamlの記述例を、図\ref{fig:setting_sample}に示す。

\begin{figure}[t]
    \setbox0\vbox{
        \vbox{project:}
        \vbox{\ \ \ \ system\_name: ``サンプルシステム''}             
        \vbox{\ \ \ \ requirement\_path: data/sample/req}
        \vbox{\ \ \ \ testsuite\_path: data/sample/testsuite}
        \vbox{processing:}
        \vbox{\ \ \ \ similarity\_threshold: 0.7}
        \vbox{\ \ \ \ weights:}
        \vbox{\ \ \ \ \ \ \ \ precondition: 0.2}
        \vbox{\ \ \ \ \ \ \ \ trigger\_operation: 0.4}
        \vbox{\ \ \ \ \ \ \ \ response\_output: 0.4}
	}
	\centerline{\fbox{\box0}}
    \caption{vitt.yamlの記述例}
    \label{fig:setting_sample}
\end{figure}

設定ファイルvitt.yamlに記述する必要がある2つの項目を、以下に示す。

\subsubsection{プロジェクト設定(project)}\label{subsubsec:project_setting}
プロジェクト設定(project)は、プロジェクトに関する情報を記述する項目である。この項目で設定する3つの項目を、以下に示す。

\begin{itemize}
    \item システム名(system\_name) \\
    システム名は、要求仕様テンプレート(\ref{sec:EARS}節参照)の「システム名」の要素に対応しており、対象システムの名称を記述する。
    図\ref{fig:setting_sample}の例では、システム名は、「サンプルシステム」と設定している。
    \item 要求仕様書のディレクトリパス(requirement\_path) \\
    要求仕様書のディレクトリパスは、入力対象の要求仕様書を格納しているディレクトリのパスである。\tool は、このディレクトリ下にあるCSVファイルを要求仕様書として読み込む。
    図\ref{fig:setting_sample}の例では、要求仕様書のディレクトリパスは、「data/sample/req」と設定している。
    \item テストスイートのディレクトリパス(testsuite\_path) \\
    テストスイートのディレクトリパスは、入力対象のテストスイートを格納しているディレクトリのパスである。\tool は、このディレクトリ下にあるCSVファイルをテストスイートとして読み込む。
    図\ref{fig:setting_sample}の例では、テストスイートのディレクトリパスは、「data/sample/testsuite」と設定している。
\end{itemize}

\subsubsection{処理設定(processing)}\label{subsubsec:processing_setting}
処理設定(processing)は、要求仕様とテストケースの対応関係を抽出する際に用いるパラメータを記述する項目である。この項目で設定する2つの項目を、以下に示す。

\begin{itemize}
    \item 類似度の閾値(similarity\_threshold) \\
    類似度の閾値は、要求仕様とテストケースの対応関係の有無を判定する際に使う実数値で、$0$以上$1$以下の範囲で指定する。
    図\ref{fig:setting_sample}の例では、類似度の閾値は、「0.7」と設定している。
    \item 対応付け要素の重み(weights) \\
    要求仕様とテストケースの対応関係の有無を判定する際、各対応付け要素間の重要度を重みとして、以下の3つを指定する。以下、3つの重みの合計が1.0になるように指定する。
    \begin{itemize}
        \item 前提条件と事前条件の重み(precondition) \\
        前提条件と事前条件の重みは、要求仕様の前提条件とテストケースの事前条件の類似度に対する重みである。
        図\ref{fig:setting_sample}の例では、前提条件と事前条件の重みは、「0.2」と設定している。
        \item トリガーと操作の重み(trigger\_operation) \\
        トリガーと操作の重みは、要求仕様のトリガーとテストケースの操作の類似度に対する重みである。
        図\ref{fig:setting_sample}の例では、トリガーと操作の重みは、「0.4」と設定している。
        \item システム応答と期待出力の重み(response\_output) \\
        システム応答と期待出力の重みは、要求仕様のシステム応答とテストケースの期待出力の類似度に対する重みである。
        図\ref{fig:setting_sample}の例では、システム応答と期待出力の重みは、「0.4」と設定している。
    \end{itemize}
\end{itemize}

なお、類似度の閾値が$0$以上$1$以下の範囲外である場合、または、対応付け要素の重みの合計が1.0でない場合、\tool はエラーメッセージを表示し、実行を停止する。

\section{\tool{}使用時の流れ}\label{sec:flow_using_tool}

ツール使用者が\tool{}を使用する際の流れを、以下に示す。

\begin{enumerate}
    \item \ref{subsec:reqspec}節で述べた要求仕様書、および、\ref{subsec:testsuite}節で述べたテストスイートを作成する。
    \item 設定ファイルvitt.yamlを記述し、初期設定(\ref{sec:config}節参照)を行う。
    \item コマンドライン上で「\$ make run」を入力し、\tool{} を実行する。
    \item 任意のWebブラウザ上で「http://localhost:8000」にアクセスし、TCVダイアグラムを確認する。
    \begin{itemize}
        \item テストケースの過不足箇所が存在しない場合\\
        \tool{}の実行を終了する。
        \item テストケースの過不足箇所が存在する場合\\
        テストケースの過不足箇所を特定し、
        要求仕様書とテストスイートの内容を確認する。
    \end{itemize}
    \item 要求仕様書またはテストスイートを修正し、3.に戻る。
\end{enumerate}
